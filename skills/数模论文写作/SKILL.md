# 数学建模论文与写作

## 1. 角色与边界

本 Skill 位于：

```text
赛题解读
→ 数学建模论文与写作
→ 国赛论文绘图
→ 最终成稿冻结
→ 最终审查
```

负责：

- 读取 `PAPER_READY` 对应的 final 文件、五份冻结合同与门禁后的工作数据；
- 核验上游已冻结的基线、候选比较、主模型、代码、结果、验证与跨问接口是否齐备；
- 把上游“模型输出 → 最终决策”的证据链准确写入正文，不重新计算或改变结论；
- 写作论文结构、公式、结果分析、摘要和结论；
- 生成绘图任务单与最终审计交接材料；
- 在生成阶段控制晦涩长句、机械过渡和 AI/模板化语言。

不要：

- 重新解释已经冻结的题意；
- 重新选择模型、修改模型数学结构、编写求解代码或运行求解器；结果缺失、失效或需重算时返回“数模审题”；
- 擅自改变题面事实、硬约束或已经冻结的分析口径；
- 擅自改变已经冻结或经验证确认的模型、阈值和结论；若候选比较、敏感性分析或模型诊断要求调整，必须给出证据，并同步更新模型说明、代码、结果文件、图表和正文数字；
- 仅为了显得高级而更换已经验证有效的模型；
- 直接生成 AI 风格的正式流程图；
- 替代最终论文审计。

若冻结题意与数据冲突，停止相关建模并报告，不要自行改口径。

## 2. 必需输入与入口门禁

启动正式写作前，必须读取上游 `paper_ready_manifest.json`，确认状态为 `PAPER_READY`、规范版本有效且其中七个文件的 SHA-256 全部匹配，并核对模型方案声明的代码入口、结果文件和验证产物可读取。不能仅凭文件名含 `_final`、报告写有 `BLOCKING=0` 或合同看似齐全自行推断通过。

从上游正式交接目录只读取：

1. `赛题解读_final.md`；
2. `Q1-QN模型方案_final.md`，其中 `N` 取实际小问数；
3. 当前冻结合同：`歧义与口径确认.md`、`建模粒度合同.md`、`约束冻结表.md`、`题意决定冻结合同.md`、`模型假设台账.md`。

禁止读取或用作回退依据：任何 backup/archive 目录（包括 `_archive/`）、`*_draft.md`、无 `_final` 后缀的旧模型方案及其他历史副本。若 manifest/final 文件缺失、状态不是 `PAPER_READY`、hash 失配，或必要代码/结果/验证产物尚未由上游生成，立即停止本 Skill，不生成正式正文、模型代码或结果；只按第 13 节报告阻塞项并返回“数模审题”。

门禁通过后，可以读取原始/清洗数据、题目要求的结果模板、已有代码与结果，以及当届官方格式、提交和 AI 规则；这些材料用于求解和成稿，不得据此重解释已冻结题意。完整交接边界见 `10_interpret_handoff.md`。

## 3. 权威优先级与冲突解释

按以下顺序处理冲突：

1. **S0**：当届全国组委会或赛区正式规则；
2. 上游 final 与冻结合同中的题意、HARD、粒度和确认决定；
3. **S1**：唯一共享规范 `../_shared/cumcm/C题规范.md` 中的写作、结构与视觉硬要求；
4. 本文件与 `09_readability_and_transitions.md` 的生成执行规则；
5. 其他模块化参考、优秀论文经验和模型偏好；
6. 示例句、建议字数和话术骨架。

同层级按以下规则解释：

- “必须、禁止、硬规范”高于“优先、推荐、建议、示例”；
- 当前执行规则可以澄清旧版建议，但不能覆盖 S0/S1 的实质硬要求；
- 示例只说明逻辑关系，不得成为固定句式；
- 历史论文中的具体模型不得当作当年必选模型。

对阶段过渡统一解释：

> **真实逻辑承接是硬要求；100—200 字、五步齐全和固定句式都不是硬要求。**

根据真实变化选择必要要素。没有新增矛盾或模型升级时，不得虚构“原方法不足”或“模型升级”。

上游已冻结的题意口径、HARD 约束、`object + semantic_role + dimensions` 对象粒度，以及 `VERIFIED` / `RESOLVED_BY_EVIDENCE` / `APPROVED_BY_USER` 决定与人工确认结果，均是写作阶段不可重新解释的事实。正文、公式、代码、结果和跨问接口必须与其一致；已确认决定只保留唯一口径，不得重新展示旧 A/B 候选。模型假设可以按合同记录的诊断、敏感性或失效条件检验，但任何调整若触及上述冻结事实，必须返回上游重新冻结，不能在写作阶段静默改写合同。

## 5. 冻结模型到论文的写作工作流

### A. 建立每问执行表

每问先明确：

```text
冻结合同 ID：
分析对象/object：
语义角色/semantic_role：
冻结维度/dimensions：
输入与输出：
决策变量/状态变量：
HARD 约束 ID/隐含约束：
题意决定 ID/人工确认决定：
上游接口：
目标或损失：
简单基线：
候选模型：
最终主模型：
验证方式：
模型输出如何转成最终答案：
结果文件及精度：
```

影响模型、代码、结果或验证的字段为空时，停止写作并返回“数模审题”补齐，不在本 Skill 内编码或求解。

### B. 问题分析只提出路线

问题分析回答：

> 问题本质 → 数据结构/难点 → 建模步骤和模型类别 → 验证 → 输出及下游用途

若最终模型需要候选比较决定，不要在问题分析中提前宣布最终模型。候选比较、选择依据和正式模型放入对应问题的模型建立部分。

### C. 核对数据结构与冻结模型一致

核对上游使用的多表主键与粒度、时间结构、重复测量、删失、类别不平衡、资源约束和不确定性是否在正文准确呈现。发现结构与冻结模型不一致时返回上游，不在写作阶段另选模型。

### D. 表述“基线 → 候选 → 主模型”的冻结证据

核心问题至少呈现上游已运行的一个简单合理基线。存在候选比较时，按上游实际证据写清：

```text
上游探索诊断
→ 已运行的简单基线
→ 实际进入比较的候选
→ 统一训练/验证口径
→ 指标与模型诊断结果
→ 已冻结最终主模型
```

不得补写上游未运行的候选，也不得仅凭散点图或写作偏好改变最终模型。复杂模型是否保留，以“数模审题”冻结的比较结论为准。

### E. 模型表达与结果溯源

- 统计/回归：依据上游结果说明数据结构、候选比较、参数估计、诊断和现实含义；
- 优化：依据上游模型依次写决策变量、目标、约束、变量域、求解器、可行性核验及基准比较；
- 风险/不确定性：依据上游冻结内容说明分布、边界、时变、相关性及已采用的情景、Monte Carlo、CVaR、鲁棒或滚动方法。

公式、表格和正文数字必须能回查到上游代码、结果文件或验证产物。本 Skill 不运行新模型来填补空值。

### F. 验证与模型类型匹配

| 任务 | 最低验证 |
|---|---|
| 回归/统计 | 显著性、区间、残差、共线性/异方差等 |
| 时间序列 | 滚动验证、MAE/RMSE/MAPE/WAPE、残差结构；MAPE 注意零值 |
| 分类 | 混淆矩阵、Recall/F1、ROC-AUC；不平衡时 PR-AUC，筛查/高风险判定必要时补 Sensitivity、Specificity、PPV、NPV |
| 综合评价 | 权重敏感性、排名稳定性 |
| 优化 | 硬约束可行性、基准比较、关键参数敏感性；求解器可提供时报告上下界或 optimality gap |
| 随机/风险 | 重复模拟、分位数/区间、收敛 |

这里只核对和表述上游已完成的验证，不新增验证计算。若缺少与模型类型匹配的证据，返回“数模审题”；不要用统一的“灵敏度分析”替代真正的模型诊断。

上表未单列的图与网络、排队、马尔可夫链、库存、GM(1,1)、模糊综合评价、DEA、目标规划、动态规划、插值/拟合、降维与判别、生产调度、稳态/差分及启发式模型，按 `../_shared/cumcm/model-validation-minimums.md` 核对。这里只确认上游证据是否齐全并据实写入论文；任何缺项、失效或版本不一致均返回“数模审题”。

## 6. 每问正文：固定功能，不固定标题

每问必须覆盖：为什么这样做、如何建立求解、得到什么、为什么可信。三级标题按实际任务动态命名，默认 3—4 个，复杂时最多约 5 个。

大问题标题后用必要的两三句完成自然引入：

```text
前文具体得到什么
→ 当前还缺什么
→ 下一步为什么这样做
```

确有新增约束、数据结构或模型升级时，再说明原方法为何不足及新结构解决什么。不设固定字数，不要求五项全部出现。

## 7. 关键边界静默自检

在大问题开头、跨问衔接、基线升级、候选转最终模型、预测转决策、结果转验证，以及其他存在明显逻辑跳跃的位置实时自检。默认静默执行，不暂停写作，不单独输出检查状态或审计文件。

内部可使用三种状态：

- `PASS`：前后逻辑可由具体对象、结果、限制或任务核验；
- `REVISE`：存在语义跳跃、模型突然出现、空泛升级理由或模板化表达；
- `NOT_APPLICABLE`：连续公式推导、定义、独立事实说明等不需要专门过渡。

依次检查：

1. 前文留下的具体结果、证据或状态是什么；
2. 当前尚未解决的任务或真实新增条件是什么；
3. 下一步方法为什么由前两项产生；
4. 跨问时实际传递了什么变量、参数、约束、候选集或结果文件；
5. 删除“进一步、在此基础上、需要说明的是”后逻辑是否仍完整。

“在上一问基础上”“进一步建立”“为提高精度”不能单独构成 `PASS`。发现明显 `REVISE` 时只定点修改相关句段，保持公式、数字、符号、模型、参数、引用和实质结论不变；不要因轻微语言偏好打断当前技术内容。

关键逻辑边界实时静默自检；每个大问题完成后集中做一次轻量“可读性—过渡—闭环”检查。只有发现明显且尚未解决的 `REVISE` 时才记录问题，并优先记入当前问题的工作备注或最终交接警告；不得为此默认生成独立检查文件。`templates/readability_pass.md` 仅作必要时的内部检查提示。

## 8. 低模板感写作

生成时直接执行，不等待全文完成后统一“洗稿”：

- 一句话尽量只承担一个主要逻辑动作；
- 一段围绕一个主要结论，句数随内容变化，不机械凑四句；
- 优先写具体对象、变量、数字、残差、约束和模型缺口；
- 能直接陈述事实，就不增加“需要说明的是、值得注意的是、需要强调的是”；
- 不重复“这说明—进一步表明—由此可见”；
- 不把普通步骤包装成“统一框架、体系、机制、路径、范式”；
- 不为每段强加“为后续提供依据”等升华句；
- 不用“先进、优越、创新性强”替代证据；
- 模型名出现前必须已有任务、数据结构、残差、约束或验证依据；
- 公式、数字、符号、参数、引用和实质结论不得因润色而改变。

详细规则与自检见 `09_readability_and_transitions.md`。逻辑槽位仅供核验，不得复制成统一话术。

## 9. 摘要

结果基本稳定后定稿：

- 三问题型：自然引入 + Q1 + Q2 + Q3 + 总结/创新；
- 四问题型：自然引入 + Q1 + Q2 + Q3 + Q4 + 总结/创新；
- 首段写现实场景/研究对象、核心矛盾、数据基础和总路线，不直接以“针对问题一”起笔；
- 首段最终排版硬性不超过 5 行；数据基础只有确实帮助理解总任务时才极短带过，不罗列附件数量、样本数和逐问模型；
- 逐问段允许“针对问题一/二/三/四”，但后续句法不得机械复制；
- 每问优先写模型职责、关键处理、核心结论、验证和 0—1 个区分度高的数字；
- 对摘要中的核心模型/算法名称和正文有证据支持的真实改进、创新点设置约 10—15 个短语级粗体锚点；不整句/整段加粗，也不把普通数字全部加粗；
- 标题、摘要正文和关键词最终占摘要页约 3/4—1 页；不足时补有效信息，不补背景废话；
- 关键词固定 5 个。

## 10. 图表正文叙事

重要图表原则上不得裸接小标题。图前说明为什么需要、回答什么、统计口径或比较对象；图后写读图结果、量化证据、模型/现实含义及下一步用途。

每张正式图按 `templates/figure_brief.md` 输出完整 Figure Brief；只有 Claim、统计口径、字段、单位、坐标/分组语义、合同 ID、数据路径和 SHA-256 都已确定，且图前/图后文字按顺序存在于所记录的正文源文件时，才标记 `READY_FOR_DRAWING`。图型候选只是建议，绘图 Skill 仍独立执行原有 Claim → Evidence → Chart Type 与 Gate。同一目的下的 2—4 张相关图优先考虑多面板。

总流程图和分问流程图按 `templates/flowchart_brief.md` 输出 Flowchart Brief，只冻结节点、边、接口、阅读顺序和正文上下文；只交给 `unflatten-ppt` 制作为可编辑 PPT，不交给普通绘图 Skill。流程图可以由队员直接在 PPT 中制作，也可以在需要时用代码生成；代码不是必需交付物，节点/箭头逻辑仍须经队员核对。

普通图表和流程图完成后，由队员在比赛时手动插入正文，核对图号、题注、正文引用、前后叙事、实际宽度和分页，再导出唯一最终 PDF。本文写作 Skill 不自动插图；详细边界见 `11_drawing_handoff.md`。

若绘图返回 `RESAMPLE_REQUIRED`，停止该图交付并返回“数模审题”重新计算、验证和冻结结果；本 Skill 随后依据新的冻结结果同步更新结果表、正文、摘要、数据 hash 和 Brief revision，旧图与旧 `figure_manifest.json` 失效。不得只重画图、在写作阶段自行重算，或让新图继续引用旧正文数字。

## 11. 公式、引用与结构

重点公式按“现实含义 → 数学定义/推导 → 公式 → 新符号/参数解释”组织。经典模型首次出现时引用可靠文献；由题意推导的公式说明来源，不强行找文献。

推荐主结构：摘要、问题重述、问题分析、模型假设、符号说明、数据预处理、各问题、模型评价/改进推广/结论、AI 工具使用声明、参考文献、附录。正式论文不设目录。

问题重述主动压缩：背景通常只用 2—4 句点明真实场景、研究对象和核心矛盾；逐问只保留“输入—任务—输出”和真正影响建模的条件。外部背景事实必须有来源，不堆政策、百科和原题复述。

符号表只保留约 10—20 个全文高频核心符号，优先控制在约半页、原则上不超过 3/4 页；按“集合/索引 → 确定性参数 → 随机参数 → 决策变量 → 辅助变量 → 风险指标”分类排列，同类连续。局部量就地解释；Final QA 删除死符号并检查参数与决策变量是否混排。

全文模型、算法、结果和真实创新点冻结后，重新终审论文标题：逐词核对术语与实际数学结构，至少比较 2—3 个候选再定稿。标题不设跨年份机械禁词表，也不沿用未经复核的工作标题。

附录必须另起一页：LaTeX 在附录标题前使用 `\clearpage`（必要时 `\newpage`），Word 插入分页符；不得直接接在参考文献最后几行之后。

具体排版、字体、页数、AI 声明和提交规则按 S0/S1 及 `06_paper_skeleton_repro_submission.md` 执行。

## 13. 失败与冲突

题意与附件冲突、单位/粒度无法统一、模型无解、参数不可识别、严重外推、硬约束无法满足、结果模板无法映射或候选比较口径不一致时，禁止强行继续。输出：

```text
BLOCKER:
证据:
影响:
建议处理:
是否返回赛题解读阶段: yes/no
```

所有冲突按第 3 节处理。共享 `C题规范.md` 中的建议字数和示例话术不覆盖关键边界静默自检规则；S0/S1 的实质硬规范保持最高优先级。
