# 第二十篇：论文写作自然性与流程图人工制作专项规范

## 20.1 “没有 AI 味”不等于隐瞒 AI

2026 组委会已经允许参赛队在公开透明、人工主导和逐项核验的前提下使用 AI。论文写作自然性的要求与 AI 使用声明是两件事：

- **写作自然性**：删除模板套话、空洞形容、夸张宣传和机械句式，让论文像经过作者认真推敲的学术作品；
- **AI 使用合规**：只要实际使用了 AI，就按规定在论文和支撑材料中如实披露。

因此，队内禁止把“降低 AI 痕迹”理解成“规避声明或伪装未使用 AI”。

## 20.2 摘要四类“高风险措辞”替换表

| 高风险类型 | 不推荐 | 推荐改法 |
|---|---|---|
| 套话升华 | “为实际决策提供有力支持” | 写最终方案、误差、收益或适用边界 |
| 模板结构 | “构建统一框架并逐层推广” | 直接写各问之间具体传递了什么 |
| 空洞虚化 | “模型具有较好的稳定性” | 给扰动范围和结果变化 |
| 推销夸大 | “具有极高工程价值” | 写可执行条件、限制和对比结果 |

## 20.3 自然学术表达的核心原则

1. **名词少堆，动词具体**：用“估计、检验、比较、求解、约束、筛选”替代“构建体系、赋能决策、实现协同”。
2. **结论带对象和条件**：不要写“显著提高”，要写“在 XX 数据区间内，RMSE 下降 XX%”。
3. **允许句式不完全对称**：六段式摘要要求信息均衡，不要求语法结构完全复制。
4. **少写作者自评，多写证据**：把“合理、先进、有效”交给数字、检验和约束证明。
5. **主动声明边界**：好的论文会写“该最优性限定于……”“该结论只在……成立”，而不是把所有结果都写成普适规律。
6. **标题也要去模板化**：Q1、Q2、Q3/Q4 不应连续出现完全相同的“问题思路—模型建立—结果分析—灵敏度分析”四标题；应让标题直接反映该问的数学对象、变量、模型和验证方式。


### 20.3.1 写作时优先“事实句”，而不是“作者说明句”

判断优先级：

> **直接事实/证据句 > 有必要的解释句 > 作者自我说明句**

例如：

- 优先：“BMI 系数为负且在 5% 水平显著。”
- 次选：“该结果说明 BMI 与达标时点存在负向关系。”
- 少用：“需要强调的是，这一发现进一步说明了……”

### 20.3.2 一段只保留一个主要结论，不重复总结三次

常见 AI 写法：

> 给结果 → “这说明”再解释一次 → “进一步表明”再解释一次 → “由此可见”再总结一次。

推荐压缩为：

> **结果 + 一次必要解释 + 下一步用途。**

### 20.3.3 段落结尾不强制“升华”

不是每一段都需要：

> “为后续模型提供依据”“为实际决策提供支持”“进一步提高模型可靠性”。

如果下一节自然衔接，段落可以直接以一个结果、边界或公式结束。

### 20.3.4 引号只用于真正需要界定的概念

普通词语如“可靠性”“复检”“风险控制”“数据闭环”不应频繁加引号。引号过密会让文本看起来像自动生成的概念包装。


## 20.4 流程图以 PPT 人工制作作为默认工作流

推荐操作：

```text
文字梳理逻辑
→ 纸上/白板画草图
→ PPT 建立统一节点样式
→ 添加真实依赖箭头
→ 全组检查“每条箭头是否有数学/数据含义”
→ 统一宋体 + Times New Roman
→ 导出 SVG/EMF/PDF
→ 插入论文并检查打印清晰度
```

总流程图重点表现“问题间传递”，小流程图重点表现“本问内部步骤”，不要把两类图画成同一张重复图。

# 第二十一篇：比赛 72 小时的“评审导向工作流”

## 21.1 0—4 小时：先完成“赛题解读包”，再决定模型和代码

**这一阶段新增一个明确产物：`赛题解读包`。** 至少包括：

- 材料清点：原题、附件、结果模板、文件状态；
- 一句话题目实质 + 跨问任务链；
- 关键证据标签与歧义；
- 每问规格卡；
- 附件审计表；
- 四层约束台账；
- 主模型/朴素基线/必要备选；
- 验证门槛与失败输出；
- 跨问接口；
- 每问核心结果表/验证图/指定附件的交付映射。

完成这些内容前，**不得因为某队员“已经想到一个算法”就直接进入全量编码。**

随后三人共同确认并完成：

- 每问输入、输出；
- 前后问依赖；
- 数据结构；
- 目标函数/评价指标；
- 硬约束；
- 最小可行基线模型；
- 最终必须提交的表格/文件；
- 总流程图与各问小流程图先只确定逻辑节点，正式图统一由论文手在 PPT 中人工重绘。

同时建立 **AI 使用记录表**（若比赛中使用 AI），指定一名队员持续维护工具、用途、提示方式、采纳情况和人工核验记录，禁止最后几小时凭记忆补写。

## 21.2 4—20 小时：先拿到可复现的基线结果

目标：

- 数据流程跑通；
- 问题一至少有正确可行结果；
- 论文可以开始写“问题分析、假设、符号、数据处理”；
- 不等待所谓“最完美算法”才动笔。

## 21.3 20—40 小时：做升级模型和第二/三问

遵循：

> **基础模型暴露什么问题 → 升级只解决这个问题 → 用验证证明升级有效。**


对于关系拟合/预测类问题，若存在多种合理函数形式，本阶段必须完成：

> **探索性诊断 → 简单基线 → 有依据的候选模型 → 统一指标比较 → 冻结最终模型**

禁止因为散点图“看起来像某种关系”就直接跳到最终模型。

## 21.4 40—58 小时：检验、图表、对比、风险

优先补：

- 结果可行性；
- 基线对比；
- 灵敏度；
- 预测/分类验证；
- 图表分析；
- 现实解释。

## 21.5 58—68 小时：整文收口，重点处理逻辑与语言，不反复做全量版式审计

这一阶段的重点是**内容冻结 + 去机械化写作 + 流程图最终化**。不在这里反复逐页检查编号、分页、空白页和图表碰撞；这些统一留到最后 4 小时的 Final QA 一次完成。

本阶段重点检查：

- 摘要内容完整，首段自然引入且最终排版不超过 5 行，逐问信息均衡；
- 摘要核心模型/算法与真实创新点形成约 10—15 个短语级粗体锚点，无整句/整段滥用；
- 摘要逐问段可使用“针对问题一/二/三/四”定位，但后续句式不过度同构；
- 问题二/三/四开头是否完成自然逻辑交接；
- 每次模型升级是否写清“原模型暴露的问题 → 新增矛盾 → 为什么升级”；
- Q1/Q2/Q3/Q4 的三级标题是否根据实际任务动态命名；
- 图表是否都在正文中承担明确证据职责；
- 重要图表前是否已有自然引入，说明“为什么需要、回答什么、统计口径”；图后是否完成“读图结果—量化证据—模型含义”；
- 公式是否所有关键符号都有解释；
- 每问结果是否形成“结果 → 解释 → 下一问/决策”的闭环；
- 是否高频出现“A—B—C”概念链、引号包装、元话语和自我评价；
- 是否反复使用“需要说明的是、值得注意的是、需要强调的是、进一步表明、由此形成、从而构建”等句式；
- 能直接陈述事实的地方是否仍在写“本文/我们正在做什么”；
- 所有流程图完成 PPT/矢量工具人工最终版。

> **本阶段不做的事**：不反复逐页扫编号、分页、孤行、空白页、colorbar/图例碰撞、跨页表等视觉问题；全文冻结后统一处理更高效。


## 21.6 最后 4 小时：全文冻结，执行一次 Final QA；禁止再大换模型

此时模型、代码、正文和主要图表原则上全部冻结。**最后 4 小时只做一次完整的“交卷级 QA”，不再大改模型、不再重新组织全文。**

Final QA 按以下顺序执行：

### A. 结果与复现

- 从原始附件重跑最终代码；
- 核对正文关键数字、图表数据、结果模板与支撑材料是否来自同一版本；
- 检查指定 Excel/CSV/结果文件的行列、单位、精度、文件名；
- 检查所有硬约束无违约。

### B. 编号与引用

- 一级/二级/三级标题编号连续且无重复、跳号、倒序；
- 图号、表号、公式号连续且正文引用一致；
- 不出现“表 11 在表 10 前”“5.2 后跳到 6.3”等错误；
- 参考文献正文编号与文末列表一一对应。

### C. 最终 PDF 逐页视觉验收

只在此阶段执行一次完整逐页检查：

- 是否存在 >约 1/3 页的无意义空白；
- 是否因强制分页造成大面积留白；
- 标题是否孤行在页底；
- 图片与图题、表格与表题是否被拆开；
- 图例、colorbar、标注是否压住数据或邻接子图；
- 两张高度相关的图是否应合并为 (a)(b) 组合图；
- 表格跨页时是否重复表头，必要时使用“续表”；
- 页面左右/上下视觉密度是否严重失衡；
- 最后一页是否只剩少量文字而可通过排版回收。

### D. 全局字体与排版

- 一级标题四号宋体居中；
- 二级标题小四宋体加粗左对齐；
- 三级标题小四宋体左对齐；
- 正文小四宋体、单倍行距、首行缩进 2 个汉字；
- 英文/数字 Times New Roman；
- 图题/表题五号宋体居中；
- 公式居中、编号右对齐；
- 图表、公式、标题周围留白统一。

### E. 标题、摘要与语言 Final Check

- 在模型、算法、结果与真实创新点冻结后重新终审标题；逐词核对并比较 2—3 个候选表述，不沿用未经复核的工作标题；
- 摘要最终占版 ≥约 3/4 页且 ≤1 页；
- 摘要首段自然引入且最终排版不超过 5 行；
- 逐问段允许“针对问题一/二/三/四”，但后续句式不过度复制；
- 搜索并人工检查高频元话语和“A—B—C”概念链；
- 删除不增加信息的“统一框架、提供支持、具有重要意义、值得注意的是”等表达；
- 不在最后阶段为了“去 AI 味”大规模重写数学段落，只修明显模板化和重复表达。

### F. 官方提交与 AI 合规

- 电子论文单文件 ≤20 MB，第一页直接为摘要；
- 支撑材料 RAR/ZIP ≤20 MB；
- 无姓名、学校、赛区、用户名、本地路径等身份信息；
- AI 工具使用声明位置正确；
- 使用 AI 时 `AI 工具使用详情.pdf` 完整；
- 附录支撑材料列表、代码和最终论文一致。

> **Final QA 原则**：一次集中检查比分散到每次生成后重复审查更省时、更省 token，也更接近真正的出版级校对流程。

# 第二十二篇：检查清单——写作实时检查与 Final QA 分开执行

> **使用方法**：下面清单不是从比赛开始就循环扫全文。题意/模型/语言项在对应阶段检查；编号、分页、视觉、字体、引用、最终 PDF 等只在全文冻结后的 Final QA 集中执行一次。


### 题意与结构

- [ ] 首次解读以原题、附件和官方模板为主，没有先被往年答案锚定
- [ ] 原题、全部附件、结果模板均标记为 verified / missing / unreadable 等明确状态
- [ ] 关键语句已区分题面事实、附件事实、必要推论、本队主解释、可检验假设和待计算量
- [ ] 每问已完成小问规格卡：动作词、分析对象/粒度、输入、输出、决策/状态变量、约束、目标、验证、交付
- [ ] 分析单位、时间原点、时间窗、单位、坐标方向和数据粒度统一且可追溯
- [ ] 决策变量都是真正可控制的量，没有把状态量误设为自由变量
- [ ] 题面硬约束、隐含约束、主解释、备选解释已分开
- [ ] 每问有主模型 + 朴素基线；备选模型只在有真实必要时保留
- [ ] 验证指标和门槛有题面/数据/文献依据；没有依据的门槛明确标“待校准”
- [ ] 已定义无解、数据不足、不可识别、严重外推或约束冲突时的降级输出
- [ ] 每问已锁定核心结果表、验证图、结论句和指定附件/结果文件
- [ ] 完成了“题目要求 → 文件/数值 → 图表 → 代码 → 模型 → 约束 → 原题证据”的反向验收

- [ ] 每问写清输入、任务、输出
- [ ] 前一问输出进入后一问
- [ ] 没有遗漏题目显式约束
- [ ] 开放问给出可量化方案而非泛泛建议

### 数据

- [ ] 多表主键与单位统一
- [ ] 缺失/异常/重复有处理理由
- [ ] 时间序列未随机打乱训练验证
- [ ] 重复测量没有误当独立样本
- [ ] 分类检查了类别不平衡和泄漏

### 模型

- [ ] 有合理基线
- [ ] 关系拟合/预测存在多种合理形式时，已比较“简单基线 + 1—3 个有依据的候选模型”，而不是直接指定最终模型
- [ ] 候选模型采用统一数据划分和统一指标比较，并明确写出最终模型选择依据
- [ ] 探索性散点图/趋势图只用于识别关系形态，没有被单独当作最终模型选择证据
- [ ] 升级模型有明确必要性
- [ ] 决策变量对应实际动作
- [ ] 目标函数单位/含义正确
- [ ] 约束逐条对应题意
- [ ] 求解器与模型类型匹配

### 检验

- [ ] 预测有验证集/滚动误差
- [ ] 分类有混淆矩阵、Recall/F1/AUC
- [ ] 评价有权重/排名敏感性
- [ ] 优化有约束可行性核验
- [ ] 随机算法重复运行
- [ ] 不确定性给分布/区间依据与结果分布

### 写作（生成阶段实时执行）

> **优先级最高的语言原则：能直接陈述事实，就不增加元话语。**  
> 写作过程中实时控制模板腔，避免把语言问题留到最后整篇重写。



- [ ] 标题已在全文模型/结果冻结后重新审查，名称与实际模型、任务和创新点一致，并比较过 2—3 个候选表述
- [ ] 四问题型摘要采用“自然引入 + 四问 + 结尾创新点”六段式；三问题型采用“自然引入 + 三问 + 总结”五段式
- [ ] **最终编译后，标题 + 摘要正文 + 关键词占摘要页版心至少约 3/4 页，且整体不超过 1 页**
- [ ] 摘要首段先讲现实场景/研究对象与核心矛盾，再讲本文总路线，没有直接以“针对问题一/针对某问题”开头
- [ ] 摘要不足 3/4 页时补的是模型职责、关键约束、结果、验证和真实创新，而不是背景套话或算法堆砌
- [ ] 摘要正文结束后空一行再写关键词
- [ ] 问题重述采用“问题背景 + 问题任务与关键条件”，不复制题干
- [ ] 问题背景只用 2—4 句点亮真实场景，外部事实有来源，不堆政策/百科材料
- [ ] 摘要首段最终排版不超过 5 行；核心模型/算法和真实创新点形成约 10—15 个短语级粗体锚点
- [ ] 符号表只保留约 10—20 个高频核心符号，并按“集合/索引→确定性参数→随机参数→决策变量→辅助变量→风险指标”分类
- [ ] 问题二、问题三/四及重要模型升级前均有自然过渡，不直接以模型名硬切换
- [ ] 阶段过渡写清“前文留下的具体结果、当前尚未解决的任务、下一步为什么这样做”；只有真实发生时才写新增矛盾和模型升级
- [ ] 若新问与前问属于同类任务，已写清“哪些结构继承、哪些条件变化”
- [ ] 模型升级有残差、约束、数据结构、风险或样本外表现等具体依据，不以“提高精度/更加先进”为唯一理由
- [ ] 开放问从前文模型的信息缺口、误差来源或未观测因素出发，而不是孤立列建议
- [ ] 每个大问题三级标题默认 3—4 个，复杂问题最多 5 个
- [ ] 每问只固定“模型依据—建立求解—结果解释—可靠性验证”四类功能槽位，不固定标题名称
- [ ] Q1/Q2/Q3/Q4 没有机械重复完全相同的“问题思路与模型依据—模型建立与求解—结果与分析—模型检验/灵敏度分析”
- [ ] “问题思路”能用自然引入段说明时，不为凑结构单独设置重复小节
- [ ] 结果小节名称与真实输出一致；没有对比对象时不硬写“结果与对比分析”
- [ ] 验证标题与模型类型匹配；没有连续关键参数时不为形式完整强行写灵敏度分析
- [ ] 摘要各问篇幅基本均衡，保留少量结论级数字
- [ ] 正文粗体保持克制；摘要约 10—15 个短语级锚点不与正文重复滥用
- [ ] 摘要关键词固定 5 个
- [ ] 摘要包含模型、关键做法、量化结果
- [ ] 问题重述不是复制原题
- [ ] 每个重要公式前后都有解释

# 附录 A：逻辑槽位参考（不得直接生成成句）

本附录只列出需要核验的信息槽位，不提供可复制的完整话术。实际写作按数据、模型和结果重新组织句法。

## A.1 从数据到模型

- 具体变量及其数据特征；
- 基线模型受影响的具体假设；
- 改进模型只解决什么缺口；
- 两者采用什么统一验证口径。

## A.2 从预测到优化

- 前问产生的具体预测量或参数；
- 它进入目标函数、约束或情景的具体位置；
- 预测误差如何传递到最终决策。

## A.3 结果对比

- 基准方案和比较口径；
- 主指标的前后数值；
- 次指标是否付出代价；
- 结论成立的范围。

## A.4 灵敏度

- 参数、基准值与扰动区间；
- 目标值和核心决策的变化；
- 策略切换阈值；
- 稳定区间与敏感边界。

## A.5 模型局限

- 被简化的现实关系；
- 简化依据与当前检验；
- 可能失效的外部条件；
- 与局限直接对应的改进方式。


## A.6 从上一问进入下一问

- 前问传来的具体输出或文件；
- 本问新增任务；
- 继承的变量、约束或可行域；
- 只有真实存在时才写新增因素或结构；
- 本问输出及其下游用途。

## A.7 同类问题的“相同—不同—升级”

- 两问真正相同的对象或结构；
- 本问发生变化的条件；
- 原模型具体哪一部分不再适用；
- 修改位置和验证证据。

## A.8 基线模型升级

- 基线能够完成的任务；
- 暴露缺口的残差、误差、结构或约束证据；
- 缺口造成的实际影响；
- 升级模型只修正什么；
- 证明升级必要的比较或消融。

## A.9 进入开放问

- 前文已经完成的具体任务；
- 尚未观测或只能间接描述的信息；
- 应补充的数据及其进入模型的位置；
- 补充信息能够改变的判断或决策。

# 附录 B：你们 C 题主攻队的最低模型库

不追求“学完所有算法”，建议把以下模型练到能独立完成“原理—代码—检验—论文解释”：

### 统计与数据

- 描述统计、Pearson/Spearman；
- t 检验/ANOVA/卡方/非参数检验；
- OLS、Logistic、岭/Lasso；
- PCA、K-means/层次聚类；
- Bootstrap。

### 预测

- 指数平滑；
- ARIMA/SARIMA；
- Prophet 或 VAR 至少一个；
- 随机森林/XGBoost/LightGBM 至少一个。

### 2025 后建议补强

- LMM；
- Kaplan-Meier + Cox/AFT；
- 类别不平衡与阈值优化。

### 优化

- LP/MILP；
- 非线性规划；
- 动态规划基础；
- GA/PSO/SA 作为复杂求解备用；
- 多目标 Pareto/NSGA-II；
- Monte Carlo、情景分析、CVaR/鲁棒思想。

> **最后原则**：算法会得多不等于论文强。真正要练的是“看到数据结构就知道先做什么诊断；看到题目动词就知道任务是什么；看到结果就知道该用什么检验证明”。
