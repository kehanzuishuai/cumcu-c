# 冻结模型叙事与术语一致性

> 文件名为兼容既有调用而保留。本参考不再提供模型决策树，也不授权写作阶段重新选模、改模、求解或补验证。

## 1. 使用边界

只依据“数模审题”已经冻结的模型方案、代码、结果、验证与跨问接口完成以下检查：

1. 模型名称与实际数学结构一致；
2. 基线、候选与主模型只写上游确实运行并冻结的内容；
3. 模型、求解器和启发式算法不混称；
4. 任务结构和选模证据先于模型名称，避免百科式介绍；
5. 结论力度与求解状态、验证结果和适用边界一致；
6. 正文中的数字、表格、图表和下游接口可回查到同一版本的冻结产物。

任何一项需要改变模型结构、候选集合、参数、代码、结果或验证时，立即返回“数模审题”重新求解、验证和冻结。本 Skill 不提出替代模型。

## 2. 术语一致性检查

| 冻结产物 | 正文必须保持的含义 |
|---|---|
| 模型 | 决策变量/状态变量、目标或损失、约束、概率或动力学结构 |
| 求解器 | 用于求解既定数学模型的软件或精确算法，不等同于模型 |
| 启发式算法 | 对既定模型搜索可行/较优解的方法，不自动证明全局最优 |
| 基线 | 上游实际运行的简单可解释参照，不得在写作阶段补造 |
| 候选模型 | 上游按统一口径实际比较的方案，不得把“曾考虑”写成“已验证” |
| 主模型 | 上游根据比较和验证冻结的最终结构 |

新增结构化模型也按同一原则表述。例如“网络流模型 + 最小费用流算法/求解器”“作业车间调度模型 + CP-SAT 求解器”“库存模型 + 情景模拟验证”，不得把工具名或搜索算法写成模型本体。

## 3. 结论力度

- `OPTIMAL` 且最优性证据成立：可以写“获得最优解”，并说明容差或 gap（可获得时）；
- `FEASIBLE`、时间限制或仅启发式求解：只能写“获得可行解/当前最好方案/近似解”；
- 验证存在警告或适用范围受限：结论必须同步保留边界；
- 上游验证缺失：停止相应结论写作，返回“数模审题”，不得用措辞弱化来掩盖证据缺口。

新增模型的最低验证证据统一见 `../../_shared/cumcm/model-validation-minimums.md`。写作只核对和解释其中已有产物，不执行验证计算。

## 4. 最小核对清单

```text
[ ] 模型名与公式/变量/约束相符
[ ] 基线和候选均有冻结运行证据
[ ] 模型、算法、求解器称谓未混用
[ ] 求解状态与“最优/可行/近似”措辞相符
[ ] 验证结论与适用边界已进入正文
[ ] 结果数字与跨问接口来自同一冻结版本
```
