# 第七篇：数据预处理——C 题很容易被低估的得分区

## 7.1 数据处理必须写“为什么”，不是只写 Python 函数


在开始清洗前先完成**附件审计**：记录文件/工作表、对象粒度、主键、单位、时间范围、连接关系、缺失异常、服务的小问及核验状态。若清洗改变样本集，应至少报告“原始 → 排除 → 合并/插值 → 最终”的样本数量链。


一段完整的数据处理应包含：

> **问题 → 规则 → 处理 → 影响**

例如：

> 附件中同一商品在不同表格中的编码口径不同，因此先依据商品编码建立主键进行自然连接；对无法匹配的记录回查原始字段，未直接删除。合并后按日期和单品聚合销量，避免同日多笔交易导致时间序列重复索引。

这比“使用 pandas.merge 合并数据”更像竞赛论文。

## 7.2 高频数据结构检查表

### 多表业务数据

- 主键是否唯一；
- 同名变量单位是否一致；
- 日期格式、类别编码是否统一；
- 聚合粒度是“交易—日—周—月”中的哪一层；
- 连接后是否造成一对多重复。

### 时间序列

- 是否存在缺日期；
- 是否有趋势、季节、节假日/周内效应；
- 是否需要平稳性检验；
- 训练/验证划分必须按时间顺序，不能随机打乱。

### 重复测量/面板数据

- 同一对象是否多次出现；
- 观测之间是否相关；
- 是否需要随机截距/随机斜率；
- 是否存在对象层级与时间层级。

### 分类数据

- 类别比例；
- 缺失机制；
- 是否存在数据泄漏；
- 特征是否使用了预测时点之后的信息。

### 异常值

不要默认删除。先区分：

- 录入错误 → 修正/删除；
- 极端但真实 → 保留并用稳健方法；
- 业务异常日 → 单独作为场景/哑变量；
- 测量离群 → 检查仪器/样本质量。

## 7.3 数据预处理的结果至少给一张“处理前后对照”

推荐表：

| 项目 | 原始 | 处理后 | 处理规则 |
|---|---:|---:|---|
| 记录数 | … | … | 去除重复/无法解析记录 |
| 缺失值 | … | … | 插值/删除/分组中位数 |
| 异常值 | … | … | IQR/业务规则复核 |
| 时间范围 | … | … | 统一统计窗口 |

当样本数量、重复聚合、数据层级、类别不平衡或最终样本构成会影响模型选择、验证或结论解释时，可增加一张紧凑的数据概览图；若处理前后对照表已经足够，则不为凑图强制生成。非互斥的缺失、重复、异常与聚合数量不得拼成饼图，图必须说明这些变化怎样影响后续模型或验证。

# 第八篇：模型建立的标准语言与“基线—升级—验证”格式

## 8.1 先写模型职责，再写模型名

推荐：

> 为刻画同一对象多次观测造成的组内相关性，本文采用线性混合效应模型，并设置对象层随机截距。

不推荐：

> 本文采用先进的 LMM 模型进行建模。

模型名只是工具，**职责与适用理由**才是建模语言。


## 8.2 阶段转换与模型升级的自然引入规范

优秀 C 题论文在进入问题二、问题三、改进模型、风险分析或开放问时，通常先解释**为什么论文需要进入下一阶段**，而不是把题号当作唯一过渡。

### 8.2.1 逻辑检查维度：承接—不足—新矛盾—升级—任务

先用必要的两三句解释为什么进入下一阶段，不设固定字数。以下五项是按实际变化选用的检查维度，不是必须齐全的段落模板：

1. **承接**：前一阶段通过【方法】得到了【具体结果】；
2. **不足**：该结果仍不能直接解决【当前任务】；
3. **新矛盾**：当前进一步出现【新约束/新数据结构/随机性/相关性/离散决策】；
4. **升级**：因此保留【可继承部分】，并引入【新增模型结构/变量/风险机制】；
5. **任务**：最终求得【本阶段输出】并通过【验证】检查可靠性。

最低通过条件是能指出“前文具体留下什么、当前为什么还要继续、下一步做什么”。不存在新增矛盾或模型升级时，省略相应维度，不得虚构不足。不得把五项依次翻译成固定句式。

### 8.2.2 不同阶段的引入重点

| 阶段转换 | 引入最应强调的内容 |
|---|---|
| 数据分析 → 预测 | 历史规律为何不能直接等价为未来，以及预测对象/时间尺度是什么 |
| 预测 → 优化 | 预测结果以何种单位、粒度和方式进入目标函数或约束 |
| 确定性 → 不确定性 | 原方案忽略了哪些波动、风险或参数区间 |
| 单目标 → 多目标 | 原目标无法同时反映哪些现实需求，需要怎样的权衡 |
| 连续规划 → 混合整数 | 新增了哪些“是否/选择/启停”类离散决策 |
| 基线 → 改进模型 | 基线残差、拟合、约束或泛化暴露了什么具体缺陷 |
| 问题二 → 问题三 | 哪些变量/约束继续沿用，哪些现实条件发生扩展 |
| 前三问 → 开放问 | 已有模型暴露出哪些信息缺口、误差来源或尚未观测因素 |
| 模型 → 验证 | 为什么“得到一个最优值/预测值”还不足以证明可信 |
| 结果 → 结论 | 数字如何转化为题目语境中的判断、边界与实际含义 |

### 8.2.3 “先讲相同，再讲不同”是非常有效的过渡方式

当新问题与上一问属于同一大类任务时，先核验并自然写出：

- 真正继承的核心变量、基础关系或可行域；
- 当前发生变化的约束、随机性、离散决策或相关结构；
- 原模型具体哪一部分不再适用；
- 对应修改及验证方式。

这种写法尤其适合：

- 确定性规划 → 随机/鲁棒规划；
- 单目标 → 多目标；
- 连续变量 → 0-1/混合整数变量；
- 独立情景 → 相关情景/Copula；
- OLS → LMM；
- Logistic → 非线性分类器。

### 8.2.4 模型升级必须先解释“原方法为什么现在不够”

不推荐：

> “为了提高模型精度，本文进一步采用 XGBoost/NSGA-II/深度学习。”

升级前必须提供：

- 基线已经完成的任务；
- 残差、样本外误差、约束冲突或数据结构证据；
- 缺口造成的具体影响；
- 新结构只修正什么；
- 证明升级必要的基线比较、消融或稳健性检验。

**原则**：

> **先有诊断，再有升级；先说明缺口，再出现模型名。**

### 8.2.5 新阶段优先从“现实机制”进入，再过渡到数学模型

进入新模型时，推荐顺序：

> **现实机制/业务矛盾 → 数学抽象 → 模型结构**

而不是：

> **模型定义 → 算法百科 → 硬套题目**

例如价格—需求阶段，应先解释价格、季节、节假日、替代关系等为何影响需求，再建立弹性/回归/预测模型；风险阶段应先解释哪些参数会波动、波动如何影响收益，再选择 Monte Carlo、CVaR 或鲁棒优化。

### 8.2.6 开放问的引入：从“前文模型暴露的缺口”出发

最后一问若要求进一步收集数据、推广或提出建议，不要突然列建议清单。优先写：

> 前述模型已从【已有任务】得到当前数据条件下的结论，但【某些参数/误差来源/外部因素】仍只能被间接刻画。为提高模型在真实环境中的解释、预测或决策能力，本问从前述模型的误差来源与未观测因素出发，分析还应补充采集的数据及其在后续模型中的具体作用。

这样开放问与前文仍然保持同一证据链。

### 8.2.7 阶段引入的三个禁忌

1. **只用题号过渡**：  
   “针对问题二……针对问题三……”连续重复，论文像答题卡而不是完整研究。

2. **模型名先于问题矛盾**：  
   还没解释为什么需要升级，就突然出现“采用某高级算法”。

3. **上一问没有真实接口**：  
   文字写“在问题一基础上”，但模型里没有任何参数、约束、候选集或输入来自问题一。

> **判断标准**：删掉阶段引入后，如果评委会不知道“为什么这一问必须这样变”，说明这段引入是必要的；如果只是把题目标题换个说法，则应重写。


## 8.3 关系拟合/预测存在多种合理形式时，必须比较候选模型后再确定最终模型

优秀论文中，最终模型通常不是“看一张散点图后直接指定”，而是通过：

> **探索性诊断 → 合理候选模型 → 统一比较 → 最终选择 → 参数解释/验证**

完成模型选择证据链。

### 8.3.1 探索性图只回答“关系可能长什么样”

散点图、LOWESS/LOESS、分组均值、趋势线等主要用于识别：

- 线性/非线性趋势；
- 单调性；
- 异方差；
- 离群点；
- 分段关系；
- 交互或组间差异的可能性。

**不能因为散点图“看起来近似线性”就直接宣布使用线性模型，也不能因为曲线略弯就直接指定高阶多项式。**

### 8.3.2 至少保留“简单基线 + 有依据的候选形式”

当关系拟合、回归、预测模型存在多种合理形式时，至少比较：

> **1 个简单可解释基线 + 1—3 个有数据/机理依据的候选模型**

候选模型来自真实诊断，而不是为了“多试几个算法”凑比较。

例如重复测量关系建模时，可以固定随机效应结构，再比较固定效应形式：

| 候选模型 | 关系形式 | 重复测量处理 | 主要目的 |
|---|---|---|---|
| M1 | 线性 | 随机截距 | 简单基线 |
| M2 | 二次项 | 随机截距 | 检查曲率 |
| M3 | 样条/平滑项 | 随机截距 | 检查更一般非线性 |
| M4 | 主效应 + 交互 | 随机截距/必要时随机斜率 | 检查条件效应 |

时间序列/预测同理，可比较季节均值、ARIMA/ETS、Prophet/树模型等，但必须保证训练—验证口径一致。

### 8.3.3 候选模型必须在统一口径下比较

根据任务选择统一指标：

- 回归/混合模型：AIC、BIC、验证 RMSE/MAE、边际/条件 \(R^2\)、残差诊断；
- 预测：滚动验证 MAE/RMSE/MAPE/WAPE、残差结构；MAPE 注意零值问题；
- 分类：Recall/F1、ROC-AUC、PR-AUC、Brier；筛查/高风险判定必要时补充 Sensitivity、Specificity、PPV、NPV；
- 生存/时点：对数似然、AIC/BIC、C-index、校准/残差；
- 优化启发式：最终目标值、约束满足情况/可行率、重复运行均值/标准差、求解时间；求解器可提供时同时报告下界/上界或 optimality gap。

推荐设置“三线表：候选模型性能比较”，使评委一眼看到**为什么最后选这个模型**。

### 8.3.4 最终选择不能只看“拟合最好”

最终模型选择综合考虑：

> **拟合/预测性能 + 残差/假设诊断 + 参数稳定性 + 可解释性 + 复杂度 + 后续决策需要**

如果复杂模型只带来极小改进，应优先保留简单模型。

推荐过渡：

> 候选模型比较表明，引入【结构】后【指标】明显改善，而继续增加【更复杂结构】的收益有限。综合泛化误差、残差诊断与解释性，最终采用【模型】作为本问主模型。

### 8.3.5 2025 类重复测量问题的推荐写法

更成熟的 Q1 逻辑应是：

> **自然引入 → 组合散点图/平滑趋势 → 候选函数形式比较 → 选定混合效应模型 → 参数估计 → 模型诊断与现实解释**

而不是：

> **小标题 → 两张散点图 → 相关系数 → 直接 LMM**

> **原则**：数据告诉我们应该比较哪些模型，比较结果告诉我们最终采用哪个模型；散点图本身不负责替作者“选模型”。


## 8.4 基线模型必须存在

C 题尤其建议建立“最简单合理基线”：

- 预测：历史均值/季节均值/线性回归/ARIMA；
- 分类：Logistic/LDA；
- 评价：等权或简单综合评分；
- 优化：确定性 LP/MILP；
- 风险：若无分布依据，先做情景边界而不是直接复杂随机模型。

升级模型时写清：

> 基线模型在【残差结构/非线性/个体差异/不平衡/非凸】方面存在不足，因此引入【升级模型】；若升级后指标提升有限，则优先保留更简单模型。

## 8.5 优化模型必须按“变量—目标—约束—求解器”写

### 变量

> 定义 \(x_{ijt}\) 为……，定义 \(z_{ijt}\in\{0,1\}\) 为……。连续变量负责“量”，0-1 变量负责“是否”。

### 目标函数

先写自然语言：

> 目标为最大化总收益，即销售收入减去采购/种植/运输/惩罚成本。

再写数学式。

### 约束

每个约束后用括号标注业务含义：

- 资源容量约束；
- 供需平衡约束；
- 轮作/顺序约束；
- 最小批量约束；
- 集中度约束；
- 整数/0-1 约束。

### 求解器

说明：

- 模型类型（LP/MILP/NLP/MINLP）；
- 求解工具（Gurobi/CPLEX/LINGO/scipy/fmincon/启发式）；
- 若用智能算法，说明编码、适应度、约束处理、停止条件、重复次数。

# 第九篇：公式排版规范——让评委“看得懂公式在干什么”

## 9.1 公式的五个固定要求

> **新增硬规范**：经典模型/算法的核心公式在首次出现时给出文献引用；自己推导的式子写清从题意定义、守恒关系、概率关系或约束逻辑如何得到。


1. **重要公式单独编号**，正文按“式（1）”引用；
2. 公式前必须有一句话说明“要表达什么”；
3. 公式后解释新符号，不让评委猜；
4. 同一符号全篇保持唯一含义；
5. 复杂约束尽量分行对齐，并在右侧/下方写业务意义。

## 9.2 变量风格

- 标量：\(x,p,c\)；
- 向量：\(\mathbf{x}\)；
- 矩阵：\(\mathbf{A}\)；
- 集合：\(\mathcal{S}\)；
- 期望：\(\mathbb{E}[\cdot]\)；
- 概率：\(\Pr(\cdot)\)；
- 0-1 变量明确写 \(z\in\{0,1\}\)。

## 9.3 优化模型公式推荐格式

先定义收益：

\[
R_{jt}=p_{jt}\min(Q_{jt},D_{jt})+\alpha p_{jt}\max(Q_{jt}-D_{jt},0)
\]

其中 \(\alpha=0\) 表示超产浪费，\(\alpha=0.5\) 表示超产部分半价出售。

再给总目标：

\[
\max P=\sum_t\sum_j R_{jt}-\sum_t\sum_i\sum_j c_{ijt}x_{ijt}.
\]

最后分组列约束，而不是把十几条塞成一团：

- **面积约束**；
- **作物—地块适配约束**；
- **不重茬约束**；
- **三年豆类约束**；
- **最小种植面积/集中度约束**；
- **0-1 与非负约束**。

## 9.4 2024 C 的一个关键排版/建模提醒

不要用

\[
x_{ij,t}x_{ij,t-1}=0
\]

简单表达“不重茬”后就不管，因为这会引入非线性。若题意允许，优先定义 \(z_{ij,t}\) 表示“是否种植”，写成：

\[
z_{ij,t}+z_{ij,t-1}\le 1.
\]

再用 Big-M 或上下界将 \(x\) 与 \(z\) 关联。这样逻辑更直观，MILP 也更容易被成熟求解器稳定处理。

## 9.5 中英文字体、字号与数字字体统一

训练稿和正式稿默认执行规范 17：

- 一级标题：四号宋体居中；
- 二级标题：小四宋体加粗左对齐；
- 三级标题：小四宋体左对齐；
- 正文：小四宋体、单倍行距、首行缩进 2 个汉字；
- 英文、阿拉伯数字、英文缩写：Times New Roman，并与对应中文保持同级字号；
- 图题/表题：五号宋体居中；
- 表格正文：默认五号，复杂表可小五；
- 数学公式采用与正文协调且全篇一致的专业数学字体；
- 图中英文、数字、坐标刻度与正文保持同一字体体系；
- 不允许同一张图或同一页中无意义混用 Arial、Calibri、Times New Roman 等多种英文字体。

字体统一的目标是让**正文—标题—公式—图表成为同一套视觉系统**。
