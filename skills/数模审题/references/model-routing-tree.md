# 模型结构决策树

本文件只负责缩小候选集，不代替题意、粒度和 HARD 约束冻结。先识别结构，再读对应专项 reference；动作词只能提示任务，不能单独触发模型。

## 路由记录的统一格式

每条实际启用的模型路线都按以下顺序写入小问模型方案，不适用的字段也要说明原因：

1. 适用任务/触发条件
2. 数据结构与前提检查
3. 朴素基线
4. 主模型/必要候选
5. 核心变量与数学结构
6. 推荐求解方法/软件
7. 必做验证
8. 灵敏度或稳健性
9. 常见误用
10. 失败后的降级/替代方案
11. 与下一问可能的接口

只记录实际进入比较的路线。没有结构证据的算法名不得进入候选表。

## 六维结构卡

每问在选模型前先填写一张结构卡：

| 维度 | 必须回答的问题 |
| --- | --- |
| 数据结构 | 横截面、时间序列、面板/重复测量、图、事件流、状态序列、空间点、矩阵还是多表关系？样本量、缺失、噪声和标签怎样？ |
| 题目动作 | 是描述、解释、预测、评价、分类、分组、路径、配置、调度、控制还是风险决策？最终要交付数值、排序、路径、策略、状态概率还是文件？ |
| 变量类型 | 连续、整数、0-1、排列、路径、集合、状态、流量或混合变量？哪些真实可控，哪些只是状态或参数？ |
| 不确定性 | 参数、需求、到达、服务、边权、状态转移或观测误差是否随机、时变、相关或只有区间？决策发生在不确定性之前还是之后？ |
| 特殊结构 | 是否真的存在网络、守恒流、排队、库存、马尔可夫状态、阶段递推、机器调度、稳态或固定步长差分结构？ |
| 规模与可解性 | 变量/约束/节点/状态/作业规模多大？是否存在 LP、MILP、网络流、动态规划或 CP-SAT 的精确结构？可否用小规模枚举核对？ |

结构卡中的每个判断都要能回查题面、附件字段、数据诊断或模型假设。关键词只用于定位证据，例如“最短”“排队”“库存”，不能替代结构检查。

## 自动缩小候选集

按以下优先级执行；前一层不满足时才进入后一层：

```text
冻结题意、对象、粒度和 HARD 约束
  -> 判定输出对象与决策变量类型
  -> 检查专门结构
       图/边/路径/流/匹配        -> 图与网络路由
       到达-服务-等待            -> 排队路由
       离散状态及转移概率         -> 马尔可夫路由
       需求-订货-持有-缺货        -> 库存路由
       阶段-状态-动作-递推        -> 动态规划路由
       作业-机器-工序-先后        -> 调度路由
       平衡方程或固定步长更新      -> 稳态/差分路由
  -> 若无专门结构，再按任务与数据进入统计、预测、评价、聚类或一般优化路线
  -> 先建立同口径朴素基线
  -> 优先精确结构：解析式/图算法/LP/MILP/网络流/DP/CP-SAT
  -> 精确路线规模失效或结构确为非凸/黑箱时，才读取启发式路由
  -> 用统一数据切分、约束口径和任务指标比较候选
  -> 冻结主模型、实现、结果、验证和失败输出
```

### 专门结构判定

| 已确认结构 | 进一步判别 | 读取 |
| --- | --- | --- |
| 节点—边关系且目标涉及路径、连通、流量、匹配或设施—需求分配 | 边权正负、单源/全源、容量/费用/供需、二部结构、设施容量与车辆路线 | `operations-state-routes.md` 的“图与网络模型” |
| 记录含到达时刻、服务时长、服务台或队长，目标涉及等待与能力 | 到达/服务分布、平稳性、顾客放弃、优先级、单台/多台 | `operations-state-routes.md` 的“排队模型” |
| 对象在有限状态间转移，目标是多步概率、稳态或吸收结局 | 状态是否互斥完备、是否一阶齐次、是否有吸收态 | `operations-state-routes.md` 的“马尔可夫链” |
| 需求、补货、持有、缺货和订货成本共同出现 | 确定/随机需求、提前期、瞬时/有限生产率、是否允许缺货、数量折扣、单周期/多周期 | `operations-state-routes.md` 的“库存/存贮模型” |
| 目标可按阶段分解，当前决策只需有限状态连接未来 | 状态是否足够、转移是否确定/随机、维数是否可控 | `operations-state-routes.md` 的“动态规划” |
| 多作业、多机器、工序顺序和不可重叠约束 | Flow Shop/Job Shop/并行机、释放时间、换型、资源与交期 | `operations-state-routes.md` 的“生产与任务调度” |
| 小样本单调序列、模糊语言评价、多同类 DMU、多变量降维/判别、无标签分组或离散点补值 | 继续检查各模型的专属前提，不因名称相似合并 | `data-evaluation-routes.md` |
| 非凸、黑箱或组合规模使已识别的精确模型无法在时限内求解 | 先保留精确小实例/下界与构造基线，再按解空间选择算法 | `heuristic-routing.md` |

## 冲突与组合规则

- 同一问可有复合结构，但必须区分主结构和接口。例如“预测需求后补货”是预测模型输出需求分布，库存模型作决策；不能把库存成本反向污染预测验证集。
- “选址—配送”先判断设施开启与需求分配是否构成 MILP/最小费用流，再判断是否还含车辆路径；不要把“距离最短”直接缩成单条最短路。
- “状态预测”若状态可观测且转移足够稳定可用马尔可夫链；连续数值序列仍按时间序列/回归处理。隐藏状态才考虑 HMM，并记录可识别性。
- “综合评价”不自动触发模糊评价。若指标和阈值都是精确数值，先用等权/透明加权、TOPSIS 等基线；只有真实模糊语义且隶属函数有依据时才进入模糊路线。
- “效率评价”不自动触发 DEA。只有多个同类 DMU、共同生产边界和多输入—多输出结构才进入 DEA。
- “优化”不自动触发启发式。存在明确 LP/MILP/网络流/DP/CP-SAT 结构时优先精确求解，启发式只能作为规模回退或对照。
- 低频博弈论、深入 PDE、变分法和最优控制不进入主路由。只有题面明确给出策略互动、空间连续场、泛函极值或控制轨迹结构且常规路线不足时，才提示另做专项论证。

## 候选比较与冻结

候选比较必须使用同一数据版本、训练/验证切分、单位、HARD 约束、目标口径和时间预算。最终冻结至少写明：结构卡、基线结果、候选结果、采用/淘汰理由、求解状态、随机种子或求解器参数、必做验证、敏感性结论、失败回退及向下一问传递的文件和字段。

若必要输出仍是 `[待计算]`、求解不可复现、验证未通过或结果文件与正文数字不一致，不得把“已完成求解”写入最终结论。
