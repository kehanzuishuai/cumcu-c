# 验收量表

每项按 `0=缺失或错误`、`1=部分完成`、`2=完整且可回查` 评分。量表增删项目后，满分随当前可评分项数量动态计算，不再使用固定总分。

完整解读必须同时满足：

1. 所有 P0 项均为 `2` 分；
2. `总得分率 = 实得分 / 当前可评分项满分`，且总得分率不低于 `90%`；
3. 不存在 `BLOCKING`；
4. 结构化合同校验通过。

总分门槛取不低于满分 90% 的最小整数，即 `ceil(0.9 × 满分)`。当前 14 项满分为 28 分，最低合格分为 26 分；未来项目数量变化时按同一公式自动换算。

| 优先级 | 项目 | 通过标准 |
| --- | --- | --- |
| P0 | 小问覆盖 | 每个编号小问均有规格卡和明确交付 |
| P0 | 证据完整性 | 题面/附件事实、推论、主解释、假设和待计算不混写 |
| P0 | 证据优先级 | 官方勘误最高，题面与官方附件同级；主解释、假设、用户决定和备选没有覆盖官方显式事实；无 `EVIDENCE_OVERRIDE` 或 `OFFICIAL_SOURCE_CONFLICT` |
| P0 | 约束覆盖 | 数字、范围、时间、空间、文件和精度约束均可检查 |
| P0 | 分析单位 | 对象粒度、重复结构、时空索引正确，无泄漏 |
| P0 | 粒度合同一致性 | 冻结合同与 Q1-QN 模型方案的对象、语义角色和维度一致，无 `GRANULARITY_CONFLICT` 或 `GRANULARITY_SEMANTIC_CONFLICT` |
| P0 | 交付忠实度 | 文件名、模板、行列、指定时刻和精度已登记 |
| P0 | 冻结门禁 | BLOCKING 为 0；数学实现未冒充题意歧义；关键口径已由证据解决、用户确认或标记为 `MODEL_DESIGN`；题意决定已写回 final；draft 已归档；无 `STALE_DECISION_STATE` |
| P1 | 模型假设披露 | 固定假设合同存在；非空条目有来源和至少一种验证/挑战路径，且不冒充题面事实或题意歧义 |
| P1 | 附件审计 | 每个附件有格式、大小/编码、结构、字段/单位、用途和风险 |
| P1 | 模型链 | 每问有六维结构卡、连贯主模型和有用基线，必要时才有备选；按统一 11 段记录模型/求解器路由，动作词未越过结构检查，工程化处理不改写 HARD 约束 |
| P1 | 验证设计 | 至少一个题型特有致命错误能被直接检验；评价指标、统计检验、精确解/基线对照或数值收敛检查与任务结构匹配，门槛明确或标 `待校准` |
| P1 | 不确定性/失败 | 关键歧义有对照；参数/结构有灵敏度或稳健性；无解、不可识别、弃权、外推和求解超时有明确降级及跨问影响 |
| P2 | 论文接口 | 表、图、结论、附件和摘要逐问映射 |

## 自动不通过条件

出现任一项即不能称为完整解读：

- 漏掉编号小问；
- 忽略必需附件或结果模板；
- 把团队假设写成题目事实；
- 用主解释、业务合理性、数据便利或敏感性分析覆盖题面/附件显式事实；
- 题面与官方附件或多个官方附件给出不兼容的同级值，却未标记 `OFFICIAL_SOURCE_CONFLICT` 并等待正式澄清；
- 歧义决定已经证据解决或人工确认，但没有传播到指定冻结合同，出现 `DECISION_NOT_PROPAGATED`；
- 会改变对象定义、数据粒度、HARD 约束、题目要求的目标、输出或交付的真正题意歧义未解决，却生成 final/paper-ready 模型方案；不得仅因数学实现会改变可行域或结果就阻塞；
- 将题面明确规定的时间、空间、主体、对象或周期粒度无证据聚合为更粗粒度，并作为 HARD 规则使用；
- 粒度合同与模型方案的同一稳定 ID 在对象、语义角色或维度上不一致；
- 正常数学实现被误标为 BLOCKING，或题意决定没有传播到模型方案；
- 已解决决定在 `赛题解读_final.md`、`Q1-QN模型方案_final.md`、Markdown 冻结合同或其他 final 文档中仍残留待确认、草稿、待冻结、旧 A/B 选项或第一阶段口径，触发 `STALE_DECISION_STATE`；
- final 目录顶层仍存在 `*_draft.md`，存在 backup 或非 `_archive/` 的归档目录，或写作交接仍读取任何 backup/archive 目录、`*_draft.md`；
- 分析单位造成主体、时间或空间泄漏；
- 模型可生成物理或流程上不可达的决策；
- 单位或时间原点混用；
- 无依据地把依赖事件当独立；
- “完全覆盖”“最佳”“风险”“效果”等仍无定义；
- 验证只有算法名、拟合图或一句“结果合理”，或不顾数据结构机械套用同一指标/统计检验；
- 仅根据动作词或模型名称套用算法，未核对数据结构、变量类型、专门结构和精确可解性；
- 存在明确 LP/MILP/网络流/DP/CP-SAT 结构却无理由优先使用启发式，或启发式只给收敛曲线而缺少多随机种子、可行率、基线及小规模精确解/上下界对照；
- 未实际计算却声称得到最终数值。

校验器中的严重度与冻结门禁分别记录：所有确定性合同错误按 `P0 + BLOCKING` 处理；P1 默认需要修复但为 `NON_BLOCKING`，不得仅因名义优先级相同就混用门禁。

## 新题集测试协议

1. 至少测试一道机理/几何题和一道数据/决策题。
2. 有条件时增加大数据、标签不确定、递归状态、动态网络或因果评价压力题。
3. 独立前向测试只向评测者提供 skill、原题和附件；不给既有解读、优秀论文、预期答案或已知缺陷提示。
4. 测试产物写入 skill 本体之外的隔离目录，例如 `赛题解读/skill-tests/<year>/<problem>/`；不得把历史输出放进 `references/` 或 `assets/`。
5. 对照原题 PDF、附件和模板，而不是对照固定措辞。
6. 按当前验收量表逐项评分，报告实得分、动态满分与得分率，并记录真实缺陷；不把风格差异当失败。
7. 只针对重复或高影响缺陷修改 skill，避免把某一年故事写成永久规则。
