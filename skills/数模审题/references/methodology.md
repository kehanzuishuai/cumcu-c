# 方法论

## 七层翻译

| 层次 | 核心问题 | 主要产物 |
| --- | --- | --- |
| 题意层 | 题目究竟要求什么？ | 一句话实质、任务链 |
| 对象层 | 分析单位和层级是什么？ | 对象与索引表 |
| 约束层 | 什么不能违反，什么只是选定口径？ | 约束与证据台账 |
| 模型层 | 变量、状态、方程、事件和目标是什么？ | 模型蓝图 |
| 求解层 | 如何可复现地得到数值结果？ | 主模型、基线、备选 |
| 验证层 | 什么证据能通过或否决结果？ | 验证矩阵 |
| 交付层 | 什么内容直接回答每个小问？ | 表、图、结论、附件和摘要接口 |

七层必须形成可回查链：

```text
题面/附件
  -> 证据标签与解释
  -> 变量、约束或假设
  -> 模型与求解器
  -> 验证结果
  -> 小问结论与指定文件
```

## 证据标签

| 标签 | 含义 | 处理要求 |
| --- | --- | --- |
| `[题面事实]` | 原题 PDF 直接给出的内容 | 记录数值、单位、范围、对象和页码 |
| `[附件事实]` | 由文件、工作表、字段、图像、视频或模板直接确认 | 记录文件位置和审计方法 |
| `[官方勘误]` | 竞赛方正式发布的勘误、补充说明或澄清 | 记录版本、发布日期和被替代内容 |
| `[必要推论]` | 由题面条件在数学、物理或时序上直接推出 | 给出推导、事件逻辑或单位换算 |
| `[主解释]` | 题面歧义下正文统一采用的可复现定义 | 明确是团队选择，并比较关键备选 |
| `[可检验假设]` | 不能只凭题面接受的前提 | 给诊断、敏感性或失效处理 |
| `[备选解释]` | 会实质改变结果的另一种合理定义 | 用于重算或稳健性，不与主结果混写 |
| `[待计算]` | 需要运行模型后才能得到 | 不得提前写成数值结论 |

只给会改变可行域、目标、样本结构、结论解释或交付的关键语句加标签，避免给普通叙述过度标注。

## 证据优先级门禁

固定优先级从高到低为：

| 等级 | 结构化值 | 可冻结用途 |
| --- | --- | --- |
| 官方勘误/补充说明 | `official_correction` | 覆盖被正式更正的题面或附件内容 |
| 题面显式文字 | `problem_explicit` | 与官方附件同级；HARD 约束、粒度、交付、对象定义 |
| 官方附件显式说明/字段 | `attachment_explicit` | 与题面同级；数据字段、模板结构、附件给定参数 |
| 必要数学推论 | `necessary_deduction` | 由高等级事实唯一推出的单位、事件或约束 |
| 主解释 | `main_interpretation` | 真正未规定处的团队统一口径 |
| 可检验假设 | `testable_assumption` | 需诊断、敏感性或失效处理的模型前提 |
| 备选解释 | `alternative_interpretation` | 未冻结的对照口径 |

执行规则：

1. 低等级项不得与高等级项冲突。若冲突，保留高等级项并报告 `P0 EVIDENCE_OVERRIDE`，禁止进入 paper-ready。
2. 题面和官方附件是同级官方显式证据，不能因数据难处理、模型更方便或业务解释更自然而被改写。二者兼容时共同解释；来自不同官方来源的同级标准化值不兼容时，直接标记 `BLOCKING: OFFICIAL_SOURCE_CONFLICT`，不得自动偏向题面或附件。
3. 只有官方勘误或补充说明高于题面与官方附件。若勘误存在，以勘误后的唯一合法含义为准；若没有勘误，同级官方冲突必须等待正式澄清。
4. 若同一来源本身存在两种合理读法，才进入人工确认；不能先选一个方便的 `[主解释]` 再把另一个降为敏感性。用户确认只能解决真正的解释歧义，不能覆盖无歧义事实或消除不同官方来源之间的冲突。
5. `[主解释]` 只有在无更高等级冲突、关键影响已确认且状态为 `APPROVED_BY_USER` 或 `RESOLVED_BY_EVIDENCE` 时才能冻结。

结构化证据字段必须分工明确：`evidence.source` 保存原题/附件原文及页码、工作表或字段位置；`evidence.value` 保存从该证据得到的标准化数学或结构含义。粒度证据使用稳定维度数组，例如 `["entity", "year", "period"]`，不得把整句自然语言复制到 `value` 后再与结构化决定比较。

## 推荐阅读顺序

1. 通读原题，理解故事和最终交付。
2. 清点全部材料，标记每个文件服务的小问。
3. 重读数字、单位、时间词、空间词、动作词、评价词和文件要求。
4. 在选算法之前，为每个小问填写规格卡。
5. 审计附件和模板；若附件改变分析单位或约束，回头修订规格卡。
6. 输出 `歧义与口径确认.md`；先解决会改变对象定义、数据粒度、HARD 约束、题目要求的目标、输出或交付的 BLOCKING 项。只影响数学实现、可行域表现或结果的选择不得在此阻塞。
7. 生成 `建模粒度合同.md` 和 `约束冻结表.md`，再锁定主解释与模型方案。
8. 在完整实现前设计验证门槛和交付结构，并用结构化合同校验下游声明。

## 自然语言到数学对象

- **名词到对象/索引**：判断一条记录究竟是人、检测、批次、试跳、帧、巷道边、作物季次、产品状态还是物理实体。
- **动作词到数学任务**：“估计/确定”对应推断或反演；“分析关系”对应统计结构；“设计/安排”对应优化；“模拟”要求状态演化；“评价”要求比较基准。
- **时间词到事件系统**：定义 `t=0`、观察时刻、决策时刻、延迟、窗口、切换事件，以及连续或离散时间。
- **空间词到几何域**：区分点、有限线段、面、实体、网络内部点、投影面积和坐标约定。
- **评价词到指标**：量化“最长”“合理”“可靠”“风险最小”“主要因素”“完全覆盖”和多目标聚合。

## 四层约束

### 题面硬约束

可由题面或结果模板直接检查。尽量写进程序可行性检查器。

### 隐含约束

由物理、概率、统计、时序、单位、数据层级或文件结构必然产生。必须写出来源或推导。

### 主解释

题面没有唯一数学含义时，论文统一使用的定义。它可复现，但不是题面事实。

### 备选解释

用于关键歧义、稳健性或主模型失效。不得把两套解释的结果混在同一张主结果表中。

## 题面事实、题意歧义与模型假设

三者必须分开：

| 类别 | 判定 | 去向 | 是否阻塞 final |
| --- | --- | --- | --- |
| 题面事实 | 高等级证据给出唯一含义 | 证据卡、HARD 约束或粒度合同 | 冲突时阻塞 |
| 真正题意歧义 | 高等级证据不能唯一确定，且不同解释会改变对象定义、粒度、HARD 约束、题目要求的目标、输出或交付 | `歧义与口径确认.md` | 未解决时阻塞 |
| 数学实现/模型设计 | 题目要求已经确定，但存在多种目标函数写法、核算方式、候选模型、跨问接口或聚合规则 | 候选模型；关键口径进入 `题意决定冻结合同.md` | 不阻塞，冻结后必须传播 |
| 普通模型假设 | 题面未规定、为完成建模而选定的参数、分布或结构设定 | 约束与假设台账或 `模型假设台账.md` | 已完整披露时不阻塞 |

AI 与人工的边界：

1. 最高等级证据只有一个标准化值时，AI 直接采用该值。若该项目曾形成候选歧义，标记 `RESOLVED_BY_EVIDENCE`；若从未形成真正歧义，则作为普通事实标记 `VERIFIED`，不进入歧义合同。
2. 最高等级证据仍有两个或更多合理标准化值，且差异实质改变模型时，标记 `BLOCKING`。AI 负责写清选项、后果、推荐和依据；用户决定后标记 `APPROVED_BY_USER`。
3. 用户决定仍受证据优先级约束，不能把明确题面事实改成更方便建模的口径。
4. 高等级证据不足但问题只是参数主值、随机分布或风险偏好时，不进入歧义合同，按普通模型假设处理。
5. 若题目要求不变，只是在选择“怎样数学化、怎样核算、怎样传给下一问或采用哪个候选模型”，按数学实现处理。关键且需要跨问复用的决定写入 `题意决定冻结合同.md`，其余留在候选模型比较或模型假设中。

普通模型假设即使影响结果或可行域也不等于题意歧义。`模型假设台账.md` 是 final 固定合同；没有普通模型假设时仍输出 `items: []`。每个非空条目记录假设陈述、来源，并至少提供一种验证/挑战路径。数值参数优先记录主值、备选值和灵敏度；独立性、平稳性、结构不变等非数值假设可记录诊断、稳健性检验、失效条件及不成立时的备选模型。敏感性分析回答“模型设定变化时结论是否稳定”，不能替代真正题意确认。

## 粒度合同与冻结门禁

`建模粒度合同.md` 是审题到建模、写作和审计的机器可检验接口。每项使用稳定 ID，至少包含对象、语义角色、冻结维度、证据等级、证据位置、状态和 `mutable`：

| 对象示例 | 冻结粒度示例 | 默认可变性 |
| --- | --- | --- |
| 决策变量 | 主体 × 对象 × 年份 × 周期 | 题面明确时 `NO` |
| 容量上限 | 对象 × 年份 × 周期 | 题面明确时 `NO` |
| 单位产出 | 对象 × 主体类型 × 周期 | 依证据判定 |
| 单价 | 对象 × 主体类型 × 周期 | 依证据判定 |
| 随机需求 | 对象 × 年份 × 周期 × 情景 | 依问题与模型设定判定 |

人工可读表和 `contract-json` 代码块必须表达同一内容。`semantic_role` 使用 `observation / parameter / state / decision / constraint / output / interface`。原始观测与下游决策即使都涉及同一业务对象，也分别建立稳定 ID；校验器只比较同一 ID 的 `object + semantic_role + dimensions`，不把“观测粒度不同于决策粒度”误判成冲突。模型方案也声明同样的三元组、符号和已实现的 HARD 约束；维度不一致报告 `P0 GRANULARITY_CONFLICT`，对象或角色不一致报告 `P0 GRANULARITY_SEMANTIC_CONFLICT`。

每个证据解决或用户确认的歧义都必须声明 `freeze_targets`，给出目标 `contract`、稳定 `id` 和 `field`。校验器比较 `decision` 与目标字段的结构化值；只在歧义文件中改了结论、没有同步写入粒度/HARD/题意决定等冻结合同，报告 `P0 DECISION_NOT_PROPAGATED`。`题意决定冻结合同.md` 再通过稳定 ID 写入模型方案的 `implemented_interpretation_decisions`，形成 `ambiguity decision → freeze contract → model plan` 的传播链。

生成 final/paper-ready 前逐项检查：BLOCKING 为 0；所有真正题意歧义均处于 `RESOLVED_BY_EVIDENCE` 或 `APPROVED_BY_USER`；HARD 约束有 `official_correction`、`problem_explicit`、`attachment_explicit` 或 `necessary_deduction` 证据；主解释不冲突；粒度、题意决定和模型假设合同已生成；确认决定已通过 `freeze_targets` 写回冻结合同；模型方案与粒度/HARD/题意决定一致；所有合同 `schema_version` 与关键字段合法。否则保留 `赛题解读_draft.md` 并标记 `INTERPRETATION_PENDING`。

结构化冻结完成后还要执行一次自然语言同步：以已更新合同为唯一来源，重新生成 `赛题解读_final.md` 和 `Q1-QN模型方案_final.md`，把草案移入 `_archive/`。任何 backup 或其他 archive 目录必须移出正式交接目录。final 报告、模型方案和全部 Markdown 冻结合同只保留最终口径，不再保留旧 A/B 候选、待确认、草稿、待冻结状态或第一阶段结论。validator 逐份扫描；发现残留时报告 `P0 STALE_DECISION_STATE`。归档文件只保留历史，写作 Skill 禁止读取任何 backup/archive 目录。

题意歧义状态只使用：

- `VERIFIED`：本来就是普通确定事实，从未真正形成候选歧义；用于证据卡、粒度或 HARD 合同，不用于关闭歧义记录；
- `RESOLVED_BY_EVIDENCE`：曾经存在候选歧义，但重核高等级证据后只剩一个合法解释；证据可来自题面、附件、官方勘误或必要推论；
- `APPROVED_BY_USER`：真正歧义已由用户明确选择；
- `UNRESOLVED`：证据不足；
- `BLOCKING`：高等级证据仍不能唯一确定，且不同解释会改变对象定义、数据粒度、HARD 约束、题目要求的目标、输出或交付。

只有 `RESOLVED_BY_EVIDENCE` 和 `APPROVED_BY_USER` 可关闭真正歧义；`VERIFIED` 可冻结普通事实。`MODEL_ASSUMPTION` 是假设台账的类型/状态，不属于题意歧义状态；只要假设陈述、来源和至少一种验证/挑战路径完整，它不阻塞 final，也不能伪装成 HARD 题意。缺少整份 `模型假设台账.md` 则阻塞 final。

## 严重度与冻结门禁

校验结果同时声明两套维度：`severity=P0/P1/P2/P3` 描述修复优先级，`gate=BLOCKING/NON_BLOCKING` 描述是否阻止冻结。`PAPER_READY` 只取决于是否存在 `BLOCKING` 项，而不是只看严重度名称。确定性的合同缺失或 schema 错误、官方证据冲突、证据覆盖、决定未传播、粒度冲突和 HARD 约束遗漏均为 `P0 + BLOCKING`。P1 默认需要修复但为 `NON_BLOCKING`；只有另有明确冻结不变量时才可标为 `BLOCKING`，且必须说明原因。

## 从解读到论文级规格

每个小问最终锁定：

1. 一个承载最终答案的主模型；
2. 一个用于校准数量级和收益的朴素基线；
3. 只为真实歧义或失效保留的备选模型；
4. 按 `model-routing-tree.md` 固定六维结构卡：数据结构、题目动作、变量类型、不确定性、网络/状态/排队/库存/调度等专门结构、规模与精确可解性；动作词不得单独触发模型；
5. 一个由上述结构证据支持、并与朴素基线同口径比较的求解路线；图算法、解析式、LP/MILP、网络流、DP、CP-SAT 等精确结构优先，只有规模/非凸/黑箱证据成立时才启用启发式；
6. 按题面、附件估计、文献、人为设定分类的参数来源；
7. 足够复现的编码、初值、工程化压缩、约束处理、终止和随机种子；
8. 与任务匹配的评价指标、统计检验、数值或规则化验证门槛；
9. 一张核心结果表、一幅验证图、一段结论和指定附件输出；
10. 无解、弃权、不可识别、求解不稳定或严重外推时的处理。

统计/回归候选、评价指标、ODE、统计检验、求解器和多目标方法的详细路由只在相关题型出现时读取 `problem-type-guides.md`；新增网络/运筹/状态、小样本预测/评价/多变量及启发式路线再由该文件指向专项 references。每条启用路线都必须写满统一的 11 段路由记录，并将必做验证、灵敏度、失败回退和跨问接口落入现有模型方案与验证矩阵。这些条目不新增题意歧义类型，也不改变 final 冻结合同或 `PAPER_READY` 门禁。

复杂算法不能替代这条证据链。
