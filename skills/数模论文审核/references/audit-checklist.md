# Final Audit 三十模块检查表

## 目录

1. 入口与题意（模块 1—5）
2. 模型、数据和代码（模块 6—13）
3. 图表、语言和摘要（模块 14—18）
4. 结构、版式和引用（模块 19—24）
5. 合规、支撑材料与交卷（模块 25—30）

每项记录 `PASS / P0 / P1 / P2 / P3 / UNVERIFIED / N/A`，并按需增加 `DEFERRED_TO_DRAWING / DEFERRED_TO_FULL / OUT_OF_SCOPE / NEED_CODE_CONFIRMATION / RECOMPUTE_REQUIRED` 阶段状态。阶段状态与严重度分开；P2/P3 可作为 `WARN`。自动脚本不确定时只能 WARN/UNVERIFIED，不能用单一 LaTeX 写法、PDF 文本提取或下一模式材料缺失制造 FAIL。

## 1. 入口与题意（模块 1—5）

### 模块 1：冻结门禁

- 检查赛题解读、建模输入、主模型、代码入口、结果文件和关键图表是否冻结。
- FULL/RECHECK 发现未完成问题、未生成的强制文件、仍变化的模型、旧图引用或冻结 hash 失配时，返回 `NOT_READY_FOR_FINAL_AUDIT`。PAPER_ONLY 不执行该冻结门禁；明确图表占位写 `DEFERRED_TO_DRAWING`。
- Final Audit 不继续建模，也不把“暂定”结果审成最终结果。

### 模块 2：题目要求覆盖

- 逐问拆出动作词、对象/粒度、输入、输出、硬约束、附加任务和指定文件。
- 建立“题目要求—论文位置—结果表/图—结果文件—状态”映射。
- 检查是否遗漏题目末句、“说明理由”“评价”“给出方案”“填写附件”等要求。
- 每问结论必须能够直接回答原题；复杂模型不能替代题目输出。

### 模块 3：结果模板与指定文件

- 核对文件存在、精确文件名、格式、工作表名、行列、字段顺序、指定时间、单位和小数位。
- 检查缺值、非法负数、越界、逻辑约束、旧版本引用和无法打开的压缩/表格。
- 结果模板视为硬约束；不符合题面指定格式通常判 P0。

### 模块 4：跨问接口

- 对每条接口记录上游输出、单位/粒度/时间口径、下游进入位置和变换方式。
- 核对代码是否真的读取或使用上游结果。
- 仅写“在问题一基础上”但模型/代码没有接口，判“假接口”。
- 跨问数值不同时，先核对是否同一方案、同一评估集、同一参数口径以及是否为联合/统一情景下的重新评估。换口径重评但说明不足通常 P2/WARN；只有同一口径仍矛盾才判 P1。PAPER_ONLY 无代码时不得直接断言接口实现失败。

### 模块 5：模型输出到最终决策的映射

- 追踪预测值、概率、评分、Pareto 解、聚类标签或参数如何变成题目最终方案。
- 阈值、折中准则、分组边界、安全库存和筛选规则必须显式说明。
- 模型指标与最终动作之间突然跳转，且缺少规则/依据时判 P1；影响强制结果时可判 P0。

## 2. 模型、数据和代码（模块 6—13）

### 模块 6：模型选择证据链

- 检查朴素基线是否存在。
- 存在多种合理形式时，核对候选模型是否使用同一数据切分和统一指标。
- 散点图只能用于探索，不能单独决定最终函数形式。
- 最终模型选择综合性能、残差/假设、稳定性、解释性、复杂度和后续决策需要。
- 反向定位“最终采用、确定选用、最优模型”等首次确定性表述；其前方应已有候选比较或可追溯的选择证据。问题分析可以提前提出由结构直接支持的模型类别，如 MILP、随机规划、混合效应模型和 CVaR 风险路线；只有线性/二次/spline、ARIMA/Prophet、Logistic/RF/XGBoost、Cox/AFT 等本应比较的最终形式被提前宣布时才报警。
- 若题面已指定模型、只有一种合理形式，或前文已完成选择证据链，可直接进入最终模型；报告必须说明该例外依据，不能机械要求凑候选。
- 复杂模型增益极小但无复杂度收益说明时判 P2；无选择依据且影响核心结论时判 P1。
- 将结构参数来源反查纳入本证据链：遇到“题目给出、附件提供、根据题设、由题目可知、数据表明”时，核对相关参数、分布、矩阵、边、阈值和权重的真实来源。本队设定/模拟/估计量冒充题设事实时判 P1。

### 模块 7：数据处理链

- 追踪原始数据 → 清洗 → 合并 → 特征 → 模型输入。
- 数据型 C 题单列“数据预处理与探索性分析”，通常 1—3 页，并给处理前后对照表或关键数据统计表；不机械凑页。
- 核对主键、连接基数、单位、日期、粒度、缺失、异常和重复。
- 检查清洗前—排除后—合并/插值后—最终样本量链。
- 当样本数量变化、重复聚合、数据层级或类别失衡影响后续模型/验证时，核对是否用紧凑数据概览图或等价表格说明；不为凑图强制生成，也不得把非互斥清洗统计拼成饼图。
- 时间序列不得随机泄漏未来；标准化、特征选择、SMOTE 等只在训练折完成。
- 同一对象重复测量不得误当独立样本；论文描述必须与代码一致。

### 模块 8：变量、符号与单位

- 查同符号多义、未定义变量、定义后未使用的核心变量、上下标漂移。
- 核对元/万元、kg/吨、日/周/月、比例/百分数、面积和时间原点。
- 决策变量必须是真正可控量，状态量或观测量不能被误设为自由决策。
- 严重量纲错误或单位错误改变结论时判 P0。
- `log D` 等对数变量未单列指数反变换、但上下文尺度明确且未影响报告值时默认 P3；若把对数尺度当原尺度并改变结论，再按影响升级。

### 模块 9：公式与模型完整性

- 检查现实含义、变量、目标函数、核心关系、约束、变量域和求解器是否齐全。
- 模型假设通常 4—6 条宽口径现实简化，不把具体分布、窗口、阈值和算法参数提前写成假设。
- 重点公式前写“为何需要/如何得到”，式后解释新符号。
- 经典模型和算法首次正式引入时引用；自推公式说明定义、守恒、概率或约束依据。
- 优化模型的变量—目标—约束—变量域不能散落到无法拼合。
- PAPER_ONLY 发现重点公式与前文定义冲突时判 `P1 + NEED_CODE_CONFIRMATION`，先要求 FULL 对照代码；只有代码也错才升 `P0 + RECOMPUTE_REQUIRED`，代码正确则只修论文，不得无代码证据直接要求重算全部结果。

### 模块 10：模型—算法—代码—结果一致性

- 建立模型/参数 → 代码模块 → 重算输出 → 冻结结果文件 → 图表 → 正文数字/结论的正向映射。
- 核对模型名称、目标项、约束、参数、特征、数据切分和求解算法。
- 正文写 CVaR、代码仅优化期望；正文写随机森林、最终代码跑 XGBoost，均判 P0。
- 对关键结果配置 hash、行列、业务主键和数值容差；代码 exit=0 不能代替结果一致。
- 图表和正文数字必须来自同一最终运行版本；摘要中的结论级数字逐项与结果文件核对。

### 模块 11：代码可复现

- 明确统一入口和运行说明；优先相对路径。
- 检查依赖、数据位置、随机种子、参数配置、运行错误和输出目录。
- 用户明确授权后运行最终入口，记录命令、退出码、运行时间和日志。
- 关键结果应可从最终代码重跑，并与运行前冻结结果比较；输出覆盖同一路径时先快照冻结文件。
- 随机算法报告多次运行波动，使用容差、分布摘要和固定种子，不机械要求文件 hash 完全相同。
- 绝对个人路径、缺失依赖、不可运行代码或结果不一致按影响判 P0/P1。

### 模块 12：模型匹配型验证与灵敏度

- 按任务类型读取 `model-validation-routing.md`。
- 检查预测、分类、统计、评价、优化和风险模型是否使用匹配验证。
- 有连续关键参数、阈值、权重、风险系数或边界时，检查连续扰动曲线及策略切换边界。
- 不存在连续关键参数时不强行要求“灵敏度分析”标题，但必须有其他可靠性验证。

### 模块 13：结构参数来源

- 对会改变最终答案的阈值、窗口、聚类数、风险系数、SKU 下限、服务水平和折中点记录：来源、候选范围、选择准则、敏感性。
- “本文取 0.7”且无依据，至少 P2；直接决定核心方案并未经验证时判 P1。
- 不得把本队选择的参数写成题面事实。
- 区分五类来源：题面/附件事实、本文建模设定、数据估计/诊断、模拟生成、文献/标准。相关矩阵、模拟边数、分布、概率、阈值、权重等均必须落入其中一类并有证据。
- PAPER_ONLY 输出简短来源矩阵：`参数/关系 | 正文声称来源 | 实际来源/证据 | 状态`。缺少原题/附件时保持 `UNVERIFIED`，不得猜测 PASS/FAIL。

## 3. 图表、语言和摘要（模块 14—18）

### 模块 14：图表内容与叙事

- 每张重要图表在正文先被引用；图前说明为什么画、回答什么、数据范围和统计口径。
- 图后给主要规律、量化证据、现实/统计意义以及如何进入后续模型或决策。
- 小标题后直接出现图表而无自然引入，判 P2。
- 核对图题、表题、图例、坐标、单位、样本范围和图中数字与正文一致。
- 对“裸接小标题”的脚本命中先作为 WARN；人工查看图前是否已有用途、问题和统计口径，图后是否有读图结果—量化证据—模型含义。
- PAPER_ONLY 遇到“待绘制/待补图/此处插入”只写 `DEFERRED_TO_DRAWING`，不判 P1/FAIL；VISUAL_ONLY 或 FULL 的最终 PDF 仍保留占位时直接判 P1。

### 模块 15：图表视觉

- 检查清晰度、字号、宋体/Times New Roman、图例遮挡、colorbar、标签重叠、刻度拥挤和多面板对齐。
- 热力图/混淆矩阵数字优先可读，深色背景自动切换文字色；对比图同尺度。
- 不同优劣方向的原始指标不得用柱高直接比较，如 AUC↑、PR-AUC↑ 与 Brier↓。
- 使用低饱和克制配色，禁止霓虹、发光、伪 3D、彩虹色和商业海报风。

### 模块 16：图表冗余

- 表用于精确查数，图用于趋势、结构和比较。
- 表和图重复同一组数字且图不增加信息时建议删除其一。
- 同一目的的 2—4 张相关图优先合成 `(a)(b)(c)` 多面板。
- 不用批量 EDA 图挤占核心结果图和验证图。
- 合并与删除属于人工语义/视觉判断；脚本只能列相同标题、相邻数据源等候选，不自动删图。

### 模块 17：正文语言与模板感

- 独立执行 `language-transition-audit.md`，不要把连接、可读性、模型适配理由混成一个笼统“AI 感”判断。
- 在大问题切换、模型升级、探索到建模、结果到验证等关键边界，检查上一段的结果、限制或新条件是否解释下一段为何出现；逻辑已自然连续时不强求显式过渡句。
- 检查超长复句、同句连续多层因果/转折/递进、抽象名词堆叠和动作主体缺失；句长与连接词计数只用于定位候选。
- 模型介绍优先核对“本题特征/约束 → 模型结构 → 适配理由 → 如何验证”，弱化与本题无关的历史、定义和通用优点。
- 建立术语一致性矩阵；同一技术概念、动作、模型和方案不得在未定义差异时换名称。重点核对“暖启动/热启动”“样本外评测/评价/评估”“超额产量/超产量”“关联情景方案/关联方案”等候选，但不得自动断言候选必然同义。
- 定位“相关方法见文献”“具体算法参见文献”“详见文献”等展示式引用；优先改为“具体方法/主张 + 就近 citation + 本题作用”，并核对引用实际支持对象。
- 统计“需要说明的是、值得注意的是、需要强调的是、进一步表明、由此形成、从而构建”等元话语。
- 检查“统一框架、递进式体系、提供决策支持、具有重要意义、效果显著、参考价值”等无证据表达。
- 控制“A—B—C”概念链、普通概念引号包装、重复“这说明—进一步表明—由此可见”。
- 摘要可用“针对问题一/二/三/四”定位；正文每问不得机械复制同一句式。
- 只定位明显元话语、引号包装、概念链和模板句，不自动进行大规模“洗稿”；是否保留由上下文判断。
- 全文约 10—20 个加粗信息锚点用于快读，重点突出模型职责、改进和结论；不得整段滥用粗体。
- PAPER_ONLY 必须把 AI/模板化语言、长句与可读性、段落/小节过渡、模型百科式表达、术语一致性分成五个 Coverage 行；不能用一个笼统的“语言已检查”代替。

### 模块 18：摘要专项

- 最终 PDF 中标题 + 摘要 + 关键词占版心约 3/4 以上且整体不超过 1 页。
- 三问为自然引入 + Q1—Q3 + 总结，四问为自然引入 + Q1—Q4 + 总结。
- 首段不以“针对问题一”起笔；逐问段篇幅基本均衡。
- 每问检查任务、模型职责、关键处理、结论和验证；不堆过程参数与模型百科。
- 关键词固定 5 个；摘要结论级数字与正文、代码完全一致。

## 4. 结构、版式和引用（模块 19—24）

### 模块 19：标题与章节结构

- 论文标题简洁泛化，不把多个具体模型名堆成算法清单。
- 问题重述采用“问题背景 + 问题任务与关键条件”，不复制题干和附件字段。
- 检查一级、二级、三级标题编号连续，无重复、跳号、倒序和错误父级。
- 每问默认 3—4 个、复杂时最多 5 个动态三级标题。
- Q1/Q2/Q3/Q4 复制“问题思路—模型建立—结果对比—灵敏度”同名结构时判 P2。
- 结果标题必须与真实输出一致；没有对比对象不写“对比分析”。

### 模块 20：页面与排版 Final Visual QA

- 只对冻结后的最终 PDF 完整执行一次。
- 把最终 PDF 每页渲染为 PNG，生成全文和分组 contact sheet；先看总览，再逐页检查并记录 PDF SHA-256。
- 逐页检查大面积空白、机械分页、标题孤行、图题/图片分离、表题/表格分离、公式难看拆分、页面过满和最后一页少量文字。
- 非特殊章节正文避免超过约 1/3 页的无意义空白。
- 跨页长表重复表头并按需标“续表”。
- 检查图表碰撞、图例/colorbar 遮挡、标签重叠和多面板对齐；页面空白指标只生成候选，不自动判 FAIL。
- VISUAL_ONLY 已经锁定绘图完成后的最终 PDF；若页面中确认出现“待绘制、待插入、此处插入流程图”等占位，属于当前模式内部的确定性 P1，不延后到 FULL。

### 模块 21：字体与版式一致性

- 一级标题四号宋体居中；二级小四宋体加粗左对齐；三级小四宋体左对齐。
- 正文小四宋体、单倍行距、首行缩进 2 个汉字。
- 英文和数字 Times New Roman；图题/表题五号宋体居中。
- 表题在上、图题在下；表格正文五号或统一小五；公式居中、编号右对齐。
- 脚本只能列字体和异常线索，最终以 PDF/Word 视觉与样式检查确认。
- LaTeX 源码单独检查首行缩进：全局 `\parindent` 是否为 2 个汉字的等价长度、普通正文是否滥用 `\noindent`、是否用全角空格/连续空格/`\quad\quad`/`\hspace` 人工模拟缩进，以及分章节或分文件设置是否冲突。
- 未显式设置 `\parindent` 时先查文档类与模板默认值，不能仅凭“没搜到”判错；源码层通过也不能替代最终 PDF 对 2 汉字视觉效果的确认。
- 已有有效 `parindent`、仅混用人工空格或局部缩进写法且最终视觉正常时默认 P3；确认章节视觉规则不一致后才升 P2。

### 模块 22：参考文献

- 文末不少于 10 篇，顶格、编号连续、格式统一，按正文首次引用顺序排列。
- LaTeX 正文引用必须由统一 citation command 生成；识别 `\cite`、`\parencite`、`\supercite` 及项目声明的等价封装，不接受手工输入 `（2）`、`(2)`、`[2]` 冒充引用。
- 普通集合、区间、数组和年份范围中的 `[4,5]`、`[0,1]`、`[2024,2030]` 不算引用，不能作为“模型附近已有引用”的证据。
- 检查正文显示样式与文末编号样式一致；citation key 在实际载入的文末文献中存在，文末无孤儿文献，编号范围与首次引用顺序合法。
- 对最终 PDF 中指向参考文献页的内部链接逐项核对。若普通 `[4,5]` 等文本被链接到 bibliography，而源码上下文没有 citation command，确认后判 P1；源码或链接目标无法映射时标 `WARN/UNVERIFIED`。
- 核验 URL/DOI/题名和作者，重点排查 AI 幻觉文献；无法联网时标记需人工原文核验。
- 输出引用完整性矩阵：正文位置、引用编号/key、当前句子主张、主题匹配、原文支持、引用位置、PDF 跳转、状态。只有题名/主题证据而没有文献全文时，`原文支持` 必须为 `UNVERIFIED`。
- 将展示式引用表达与引用位置交叉核验；“详见文献”本身不能说明 citation 支持的是哪个模型、性质或主张。
- PAPER_ONLY 将“引用格式、引用跳转、引用语义正确性、数量与正文对应关系”分成四个 Coverage 行，不得以“≥10 篇”替代其他检查。

### 模块 23：模型与公式来源

- 检查 LMM、Cox、AFT、XGBoost、CVaR、NSGA-II、Prophet、报童模型等首次正式出现处是否就近引用；模型先介绍、引用隔两段才出现通常不能支持首次引入。
- 外部阈值、行业事实、标准和外部数据必须引用。
- 从题意自行推导的公式无需硬找文献，但必须写清推导路径。

### 模块 24：模型评价、局限与结论

- 优点只写正文已有证据支持的内容。
- 最后一级标题合并为“模型评价、改进推广与结论”，内部再分优点、局限、改进推广和主要结论。
- 局限不超过 3 条，写具体失效边界和当前可接受理由，不使用自毁式语言。
- 每个局限对应改进；改进具备可操作性。
- 结论按题目顺序给出结果、对比、解释和边界；不夸大因果、适用范围和工程价值。

## 5. 合规、支撑材料与交卷（模块 25—30）

### 模块 25：AI 使用合规

- 参考文献之前存在一级“AI 工具使用声明”，文本与实际使用一致。
- 使用 AI 时存在 `AI 工具使用详情.pdf`，包含工具/版本、用途环节、提示方式/过程、采纳修改和人工核验。
- 论文声明、内部 AI 日志和详情 PDF 一致；“只润色”与实际模型/代码使用冲突时判 P0。
- 使用本审查 Skill 也应进入 AI 使用记录。
- PAPER_ONLY 只检查论文内声明是否存在、位置和措辞是否一致；`AI 工具使用详情.pdf` 未提供写 `DEFERRED_TO_FULL`，FULL 仍缺失再按 S0 判定。

### 模块 26：匿名

- 扫描 `.tex/.md/.py/.m/.ipynb/.xlsx/.csv/.txt/PDF/README`、代码注释、文件名及 PDF/DOCX/XLSX/图片 EXIF 元数据。
- manifest 明确列出队员姓名、学校、学号、报名号和用户名；命中这些身份词、含用户名的个人路径时高优先级报警。
- 普通外部邮箱、参考文献中的 GitHub 地址、未命中项目身份词的 Author/Creator 字段只记人工确认，不直接判身份泄露。
- `C:\Users\...`、`/Users/...`、`/home/...` 等明确个人路径同时是匿名与复现风险；通用 `/root`、`/workspace` 等环境路径只作低优先级提示。

### 模块 27：支撑材料

- manifest 使用 `has_support_materials=true/false` 明确声明。有支撑材料时，附录文件清单与实际内容一致；包含 README/支撑材料说明、完整可运行代码、必要外部数据、中间结果和 AI 详情。
- `has_support_materials=false` 时不要求 support 文件夹；检查附录是否写“本论文没有支撑材料”。未使用程序时还写“本论文没有用到程序”。
- `ai_used=true` 时必须有 AI 工具使用详情，不能同时声明无支撑材料。
- 清理旧代码、缓存、无关 notebook、临时图、重复压缩包和过期结果。
- 保留运行说明、相对路径、依赖和统一入口；不得把 `.aux/.log/.synctex.gz` 等构建垃圾作为交付物。
- 本模块在 PAPER_ONLY 为 `OUT_OF_SCOPE / DEFERRED_TO_FULL`；不得因代码、result.xlsx、支撑包或构建垃圾未提供而给 P0/P1。

### 模块 28：交卷文件

- 电子论文为单个 PDF/Word，≤20 MB，第一页为摘要，不含承诺书/编号页，无目录，正文 ≤30 页。
- 支撑材料为 RAR/ZIP，≤20 MB，文件名符合当届通知且可正常解压。
- 附录与纸质/电子版内容一致；页码、匿名和文件版本全部确认。

### 模块 29：最终反向证据链

- 对每问核心结论、强制结果文件、摘要数字和创新建立完整反向链。
- 逐层核对：结论 → 表/图 → 冻结结果 → 重算结果 → 代码 → 模型/参数 → 变量/约束 → 原题/附件。
- 每问至少抽查一条核心结论；摘要全部结论级数字必须覆盖。可机器比对的层用 hash/行列/主键/容差，语义层由人工确认。
- 核心链任一层断开，不能判 READY；按是否改变最终答案判 P0/P1。

### 模块 30：报告与权限边界

- 输出总状态、审查范围、P0—P3 数量、BLOCKER、逐项发现、反向证据链和修复顺序。
- 每个发现包含位置、证据、规则、风险、建议和是否可确定性自动修复。
- 默认只报告；除非用户明确要求，不修改文件。
- 文件缺失、编号、路径、大小、hash/行列/容差等确定性事实可自动判断；模型合理性、阈值/权重依据、AI 感和视觉美观只能提示人工确认。
- 数学/学术判断只报告，不自动换模型、改阈值、重选参数、改变假设或结论；语言只定点定位，不自动大规模改写。
- PAPER_ONLY 使用 `PAPER_AUDIT_*` 总状态并单列 Deferred 表；RECHECK 只复核旧问题及直接受影响依赖，不重新审无关模块。
