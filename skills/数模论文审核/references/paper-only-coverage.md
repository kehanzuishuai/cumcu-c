# PAPER_ONLY 强制覆盖协议

## 1. 目的

PAPER_ONLY 是按预定范围完成的论文内部审查，不是“找到一个问题就停止”的快速扫描，也不是缩小版 FULL。即使只提供一种论文文件，也必须对本文件列出的 16 个核心模块逐项交账；完成后使用 `PAPER_AUDIT_PASS / PAPER_AUDIT_COMPLETE_WITH_WARNINGS / PAPER_AUDIT_COMPLETE_WITH_BLOCKERS`。只有论文本身缺失或不可读，才用 `INCOMPLETE_AUDIT_SCOPE`。

## 2. 覆盖状态

Coverage 状态与 P0—P3 严重度分开：

| Coverage 状态 | 使用条件 |
|---|---|
| `PASS` | 已实际检查，有可定位证据，且该模块在 PAPER_ONLY 可见范围内未发现问题 |
| `WARN` | 已实际检查，存在 P2/P3 或需要人工注意的非阻断问题 |
| `FAIL` | 已实际检查，确认存在 P0/P1 |
| `UNVERIFIED` | 缺少源码、最终 PDF、原题、文献全文或可靠工具，无法完成该模块的必要证据链 |

不能把“脚本没有报警”“没有提到”“没找到关键词”写成 PASS。一个模块同时存在确认问题和未核验部分时，Coverage 填 `FAIL` 或 `WARN`，并在证据栏补充剩余 `UNVERIFIED` 范围。

### 模式边界与延后项

以下项目不属于 PAPER_ONLY，不进入 P0/P1、FAIL 或论文内 UNVERIFIED 计数：

| 项目 | PAPER_ONLY 状态 | 转交模式 |
|---|---|---|
| 代码运行与复现 | `DEFERRED_TO_FULL / OUT_OF_SCOPE` | FULL |
| Excel/CSV/冻结结果及 hash/容差一致性 | `DEFERRED_TO_FULL / OUT_OF_SCOPE` | FULL |
| 支撑材料目录、压缩包、README 和构建垃圾 | `DEFERRED_TO_FULL / OUT_OF_SCOPE` | FULL |
| `AI 工具使用详情.pdf` 是否存在和内容完整性 | `DEFERRED_TO_FULL / OUT_OF_SCOPE` | FULL |
| 最终 PDF 逐页视觉结论 | `DEFERRED_TO_FULL / OUT_OF_SCOPE` | FULL / VISUAL_ONLY |

正文中的 AI 工具使用声明、论文内部数字、公式、图表叙事、引用和匿名仍属于 PAPER_ONLY。报告必须单列 `Deferred to FULL`，不能把“当前没提供”写成“最终缺失”。

### PAPER_ONLY 强制执行顺序

人工/语义审查必须依次完成：

1. 题目覆盖 + 模型/结果闭环；
2. 跨问接口 + 模型输出→最终决策；
3. 模型选择 + 题面事实/结构参数来源反查 + 验证；
4. 连接过渡 + AI/百科式语言 + 术语一致性；
5. 引用格式/跳转/语义正确性；
6. 压缩冗余 + 结构；
7. 段首缩进等源码排版。

自动脚本可以在人工通读前一次性收集确定性证据和候选，但不得按脚本命中顺序审正文，也不得在前三步完成前只报告文献数量、缩进或微格式。七步全部执行后，再按严重度和修复优先级整理报告。

## 3. 必须逐项覆盖的核心模块

最终报告必须逐行保留以下模块，不得合并到笼统的“语言”“引用”或“模型”结论中：

| 核心模块 | 最低检查动作 | 常见缺证 |
|---|---|---|
| 段落与排版源码 | 检查 `\parindent`、异常 `\noindent`、人工空格缩进和章节间规则一致性 | 无 LaTeX/Word 样式源码 |
| AI/模板化语言 | 检查元话语、概念包装、机械句式和无证据形容词，人工确认上下文 | 只有图片型 PDF |
| 长句与可读性 | 检查一长句多职责、多层逻辑连接、指代不清和抽象名词堆叠 | 无可提取正文 |
| 段落/小节过渡 | 阅读关键边界，判断上一段结论是否解释下一段为何出现 | 无可提取正文/章节缺失 |
| 模型百科式表达 | 检查是否以通用定义和优点替代本题适配理由 | 无可提取正文 |
| 术语一致性 | 建立规范名称表，核对同一技术概念、动作、模型和方案是否无定义地换名称 | 无可提取正文/缺少项目术语表 |
| 问题分析与最终模型边界 | 反查首次确定性选模表述前是否已有比较证据 | 问题分析或模型建立章节缺失 |
| 模型选择证据链 | 检查诊断、基线、候选、统一比较和最终选择依据；反查题面事实与模型自设参数的来源 | 无原题/附件时来源声明只能 UNVERIFIED |
| 跨问接口 | 检查上游输出、单位/粒度、下游进入方式和实际文字映射 | 无代码时不能确认实现 |
| 模型输出→最终决策映射 | 检查预测/评分/概率/解集如何变成题目方案 | 无原题时不能确认全部交付要求 |
| 图表正文叙事 | 检查已完成图表的图前用途/口径与图后量化证据/意义；占位图写 `DEFERRED_TO_DRAWING` | 只有源码无当前渲染时视觉部分缺证 |
| 公式与符号 | 检查现实含义、定义、单位、变量域、编号与符号一致 | 图片型 PDF 或公式不可提取 |
| 引用格式 | 检查统一 citation command、正文与文末编号样式、手工伪引用 | 无 LaTeX/Word 域代码 |
| 引用跳转 | 检查 citation key → 文末文献 → 最终 PDF 内部链接，排查错误链接 | 无最终 PDF 或 PDF 无链接注释 |
| 引用语义正确性 | 逐条核对正文主张、主题匹配、原文支持和引用位置 | 无文献全文时原文支持必须 UNVERIFIED |
| 参考文献数量与正文对应关系 | 检查 ≥10、编号连续、正文有条目、文末无孤儿、首次引用顺序 | 文末列表或源码不可读 |

不得在首个 P1/P2 后停止。只有论文文件整体不可读时才能停止正文阅读，但仍须输出 16 行 Coverage，并把受影响项标为 `UNVERIFIED`。

## 4. 段首缩进源码审查

S1 要求正文统一首行缩进 2 个汉字。PAPER_ONLY 的源码层检查包括：

1. 定位全局 `\parindent` 设置；`2em`、`2\ccwd` 或模板提供的等价实现可作为正向证据。未显式设置时先检查文档类/模板，不能仅因没搜到 `\parindent` 判 FAIL。
2. 列出正文中的 `\noindent`，区分题注、列表、公式后说明等合理用法与普通正文段落的异常取消缩进。
3. 检查段首全角空格、连续普通空格、`\quad\quad`、`\hspace{2em}`、`~~` 等人工模拟缩进。
4. 检查局部环境、章节或分文件是否修改 `\parindent`，造成不同章节规则不一致。
5. PAPER_ONLY 只给源码层结论；最终呈现是否确为两个汉字，转交 VISUAL_ONLY 对最终 PDF 确认。

明确的全局零缩进且最终视觉确实不符合规范通常为 P2；已有有效 `parindent`、只混用人工缩进/局部 `\noindent` 且视觉正常时默认为 P3。源码候选不能单独证明版式失败；源码缺失时本模块为 `UNVERIFIED`，不能用 PDF 目测冒充源码检查。

## 5. 引用四层核验

### 5.1 源码命令与显示格式

- 正文文献引用必须由统一的 LaTeX citation command 生成，如 `\cite`、`\parencite`、`\supercite` 及项目明确声明的等价封装。
- 不允许手工输入 `（2）`、`(2)`、`[2]`、`[2,3]` 冒充文献引用。
- 普通集合、区间、数组和年份范围中的 `[4,5]`、`[0,1]`、`[2024,2030]` 不是文献引用；不得因为外形像编号就算作“附近已有引用”。
- 核对正文显示样式与文末编号样式一致。若文末为 `[2]`，正文手工写成 `（2）`，属于格式、生成方式和跳转三重错误。

确认的手工伪引用、正文/文末编号样式冲突通常判 P1。正则命中只能生成候选；必须结合句子职责和源码环境排除公式、区间、列表编号及自定义合法 citation 封装。

### 5.2 citation key 与文末条目

- 每个 citation key 必须解析到实际载入的 `.bib` 条目或 `\bibitem`。
- 文末条目必须在正文真实使用；编号按正文首次引用顺序排列，编号连续。
- 模型、算法、统计方法、外部阈值、标准、数据和事实的首次正式出现应就近引用。同一句或紧随其后的直接说明优先；隔两段才补引用通常不能证明首次引入已经得到支持。
- 题意、定义、守恒关系或本队自行推导的公式不强制引用，但应说明推导依据。

### 5.3 最终 PDF 跳转与错误链接

对最终 PDF 中所有指向参考文献页的内部链接做检查：

1. 正常 citation command 生成的编号应能跳到对应文献。
2. 跳转目标的编号、题名或 citation key 映射应一致。
3. 若 PDF 某个 `[4,5]`、`[0,1]`、年份区间或数组能跳到参考文献，而对应源码上下文没有 citation command，记录为错误文献超链接候选。
4. 若可从 PDF 注释和源码上下文共同确认该普通文本被链接到 bibliography，判 P1；若只能看到可疑链接但无法完成源码映射，标 `WARN` 或 `UNVERIFIED`，不得假装已验证。
5. 无最终 PDF、PDF 链接注释被扁平化或工具不能读取目标时，本模块必须为 `UNVERIFIED`。

### 5.4 引用语义与位置

对每一次正文引用先写出“当前句子声称什么”，再判断文献是否支持：

- `主题匹配`：题名、摘要或关键词是否与该主张同一主题；
- `原文支持`：文献正文是否真的给出该方法、性质、结论或适用边界；
- `引用位置`：引用是否紧跟被支持的主张，而不是悬挂在整段末尾或隔段出现；
- `力度匹配`：文献只报告相关性时，正文不得写成因果；文献介绍模型时，不能据此声称本题性能优越。

只有题名/摘要可见时，可以判断主题匹配，但 `原文支持` 必须为 `UNVERIFIED`。不能因为题名看起来相关就给引用语义 PASS。

### 5.5 展示式引用表达

把“相关方法见文献[10]”“具体算法参见文献”“详见文献”“可参考相关文献”等列为语言与引用位置的交叉候选。它们往往只展示“这里有引用”，却没有说明该文献支持的方法、性质或主张。

优先采用“方法名/具体主张 + 就近 citation + 本题中的作用”，例如写成“采用 Gaussian Copula\cite{key} 描述变量间的尾部相关”，而不是“相关方法见文献\cite{key}”。不得为消除展示式表达而删除真实引用；应把 citation 移到其实际支持的方法名或句子主张之后。

单个局部表达通常为 P3；反复出现、明显造成模板感或使支持对象不清时为 P2。若因此导致经典模型首次出现无就近引用、引用悬挂或主张与文献错配，则按引用问题升至 P1/P2。

## 6. 模型百科式表达与真实过渡

模型段落优先检查：

> 本题特征或约束 → 对应模型结构 → 为什么匹配 → 如何验证

下列表达是重点候选：

- “这种方法属于词典序多目标优化方法，该方法适用于……”；
- “X 模型是一种广泛用于……的方法”；
- “该模型具有精度高、适应性强、鲁棒性好等优点”。

若主要篇幅在介绍模型一般能做什么，而没有连接本题变量、约束、数据结构、基线缺口或验证证据，通常判 P2；大段重复、明显替代核心建模依据或形成统一模板时可升 P1。必要定义、实际使用的结构与参数、适用前提和可靠引用应保留。

连接与过渡必须检查真实语义关系，至少覆盖：探索分析→候选模型、候选比较→最终模型、基线→升级模型、模型→结果、结果→验证及 Q1→Q2→Q3/Q4。不要统计“进一步、在此基础上”的数量来代替审查；自然连续时无需补显式过渡句。

### 模型路线与最终模型的边界

问题分析可以提前提出有明确结构依据的模型类别或路线，例如：二元/整数决策与线性约束对应 MILP，情景不确定性对应随机规划，重复观测对应混合效应模型，尾部风险对应 CVaR。出现这些名称不等于“提前锁死最终模型”。

真正需要报警的是“先宣布最终答案，后补选择证据”：本来应通过候选比较确定的函数形式或算法（如线性/二次/spline、ARIMA/Prophet、Logistic/RF/XGBoost、Cox/AFT），在比较前被写成“最终采用、最优、已证明更好”。先判断结构路线是否已由变量、约束和数据结构唯一或强烈限定，再判断是否存在逻辑倒置。

### 题面事实与模型自设参数来源反查

本项并入“模型选择证据链”，不新增第 17 个 Coverage 模块。通读正文中的“题目给出、题设给定、附件提供、根据题设、由题目可知、数据表明”等来源性表述，只要涉及模型参数、分布、相关系数、关系/相关矩阵、模拟边、概率、阈值或权重，必须反查原题或附件。

实际来源只能如实归类为：题面/附件事实、本文建模设定、数据估计/诊断、模拟生成、文献/官方标准。“数据表明”还要说明是原始附件数据、本文清洗后数据，还是模拟情景数据。

- 原题/附件能直接定位，且正文来源表述准确：PASS。
- 本队设定、模拟或估计量已如实说明方法和依据：按参数证据充分性判 PASS/WARN。
- 确认属于本队设定、模拟或估计，却写成题设/附件给定：P1/FAIL。
- 未提供原题/附件，或无法确认实际生成方法：UNVERIFIED，不得猜测 PASS/FAIL。

## 7. 证据升级与跨问口径

### 7.1 图表占位

- PAPER_ONLY：明确“待绘制/待补图/figure placeholder”写 `DEFERRED_TO_DRAWING`，图表 Coverage 可 WARN/UNVERIFIED，但不得 FAIL。
- VISUAL_ONLY：最终 PDF 中确认“待绘制/待插入/此处插入”等占位，直接 P1。
- FULL：最终论文仍有占位，升为 P1；若导致题目关键结果完全缺失，再按影响判断是否更高。

### 7.2 论文公式冲突

PAPER_ONLY 确认重点公式与前文定义冲突时，写 `P1 + NEED_CODE_CONFIRMATION`：只要求 FULL 核对代码、冻结结果和正文使用口径。不得直接要求“重算全部结果”。

- FULL 发现代码按正确公式计算：改为 `PAPER_CORRECTION_ONLY`，只修论文公式、符号解释及受影响引用。
- FULL 发现代码也使用错误公式：升级 `P0 + RECOMPUTE_REQUIRED`，只重算受影响链并同步更新结果、图表和正文。

### 7.3 跨问数值差异

遇到 Q2/Q3 等位置出现不同数值，依次核对：是否同一方案、同一评估集、同一参数口径、是否在联合情景/统一场景下重新评估。

- 方案不同：不构成同一结果冲突；说明对象即可。
- 同一方案但评估集、情景或参数口径改变：通常 P2/WARN，要求明确写“重评口径”和原场景数值的关系。
- 同一方案、同一评估集、同一参数口径仍矛盾：P1；进入 FULL 后再判断是否来自代码/结果错误。

### 7.4 低风险表达与维护项

- `log D` 未单独写指数反变换，但上下文尺度清楚且结果未错：P3；若正文把对数尺度当原尺度并改变结论，再升级。
- 已有有效 `parindent` 但人工缩进混用、视觉正常：P3。
- 构建垃圾、缓存和旧工程文件：PAPER_ONLY 不重点审，列 `DEFERRED_TO_FULL`；FULL 再检查最终支撑包。
- “可以写得更好”不等于模型有问题；只有新增证据证明影响数学含义、结果或交卷规则时才升级。

## 8. 术语一致性专项审查

先建立项目术语表，再通读全文核对同一技术概念、动作、模型或方案是否固定名称。重点候选包括“暖启动/热启动”“样本外评测/评价/评估”“超额产量/超产量”“关联情景方案/关联方案”。这些组合只用于定位，不能自动断言它们在当前论文中必然同义。

对每组变体回答：是否指向同一对象；若同义，全文采用哪个规范名称；若不同义，首次出现处是否明确给出区别。缩写与全称可并存，但应在首次出现时建立对应关系，后文不要在无说明时改变指代。

| 技术概念 | 出现变体 | 位置 | 是否同义 | 统一名称/区分定义 | 状态 |
|---|---|---|---|---|---|
| … | … | … | PASS/WARN/UNVERIFIED | … | PASS/WARN/FAIL/UNVERIFIED |

同一核心概念反复换名、影响模型—结果—方案追踪时通常为 P2；单个笔误为 P3；若换名改变数学含义、变量口径或最终决策映射，则升至 P1。只有一种写法出现并不自动证明全文术语一致，仍需人工核对同义表达。

矩阵保持简短，只收录涉及模型参数、结构、关系、分布、阈值、权重和模拟生成的来源性声明；不要把普通题意重述全部抄入。

## 11. 引用完整性矩阵

所有正文引用 occurrence 都应进入矩阵；同一位置的联合引用可合并为一行，但不能只抽查“看起来有问题”的引用。若篇幅很大，可把矩阵作为报告附表，正文汇总 FAIL/WARN/UNVERIFIED。

| 正文位置 | 引用编号/key | 当前句子声称什么 | 主题匹配 | 原文支持 | 引用位置 | PDF 跳转 | 状态 |
|---|---|---|---|---|---|---|---|
| … | … | … | PASS/WARN/UNVERIFIED | PASS/FAIL/UNVERIFIED | PASS/WARN/FAIL | PASS/FAIL/UNVERIFIED | PASS/WARN/FAIL/UNVERIFIED |

矩阵中任何 `原文支持=UNVERIFIED` 的行，整行不得给 PASS。若文献全文不可得，应明确列出需要补充的 DOI、URL、PDF 或原文页码。
