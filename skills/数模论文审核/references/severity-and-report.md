## 1. 总状态

按以下顺序判定，只能选择一个：

| 状态 | 判定条件 |
|---|---|
| `NOT_READY_FOR_FINAL_AUDIT` | 核心模型/结果/文件未冻结，存在审查入口 BLOCKER |
| `PAPER_AUDIT_PASS` | PAPER_ONLY 的 16 个论文内模块已完成且无确认问题；延后到 FULL 的交付项不影响本状态 |
| `PAPER_AUDIT_COMPLETE_WITH_WARNINGS` | PAPER_ONLY 已按范围完成，无 P0/P1，但有 P2/P3、论文内 UNVERIFIED 或 `DEFERRED_TO_DRAWING` |
| `PAPER_AUDIT_COMPLETE_WITH_BLOCKERS` | PAPER_ONLY 已按范围完成，论文内部确认存在 P0/P1；不代表代码或交付包已审 |
| `INCOMPLETE_AUDIT_SCOPE` | 当前所选模式自身必需材料缺失或不可读，如 PAPER_ONLY 没有可读论文、VISUAL_ONLY 没有最终 PDF；不得用于表示有意延后的代码/支撑材料 |
| `NOT_READY_TO_SUBMIT` | FULL 审查已执行，但仍有 P0 |
| `READY_AFTER_PRIORITY_FIXES` | 无 P0，但仍有未处理 P1 |
| `READY_WITH_WARNINGS` | 无 P0/P1，仅有 P2/P3 或明确接受的低风险问题 |
| `READY` | FULL 范围齐全，P0/P1/P2 均清零，P3 不影响交付且已人工接受 |

不能因 PASS 数量多而抵消一个 P0。`PAPER_AUDIT_*` 只评价论文内部，不是可交卷结论；只有 FULL 可以给 `READY*`。

### 阶段状态与证据升级

阶段状态不等于严重度，发现项可同时写 `P1 + NEED_CODE_CONFIRMATION`：

| 阶段状态 | 含义 | 后续动作 |
|---|---|---|
| `DEFERRED_TO_DRAWING` | PAPER_ONLY 已看到明确图表占位，但图尚未进入最终成品 | 绘图完成后在 FULL/VISUAL_ONLY 复核；PAPER_ONLY 不判 FAIL |
| `DEFERRED_TO_FULL` | 代码、结果文件、支撑材料、AI 详情等不属于 PAPER_ONLY | FULL 核验，不计入 PAPER_ONLY 完成度 |
| `OUT_OF_SCOPE` | 当前模式明确不执行该检查 | 在报告中列出目标模式，不写 FAIL |
| `NEED_CODE_CONFIRMATION` | 论文内部冲突已确认，但是否影响实际结果尚无代码证据 | FULL 对照代码和冻结结果 |
| `PAPER_CORRECTION_ONLY` | FULL 确认代码/结果正确，错误只在论文表达 | 只修论文及受影响引用，不重算 |
| `RECOMPUTE_REQUIRED` | FULL 确认代码或结果链也错误 | 升级严重度，重算受影响结果并更新图表/正文 |

升级必须有新增证据，不能仅因进入 FULL 自动提高严重度。

## 2. 严重度

### P0 — 必须修，否则不能交

典型情形：

- 漏答题目要求或强制结果文件缺失/格式错误；
- 结果违反硬约束、单位错误改变答案；
- 论文模型、代码、结果和附件实质不一致；
- 摘要关键数字与正文/代码冲突；
- 代码无法生成核心结果；
- 电子论文、页数、大小、匿名、AI 声明或支撑材料违反 S0；
- 明确命中队员/学校/学号/用户名等身份泄露、虚假 AI 声明或关键引用造假；
- 核心结论的反向证据链断裂。

### P1 — 高优先级学术/交付风险

典型情形：

- 模型输出到最终决策之间缺少规则；
- 前后问声称继承但真实接口不清或未实现；
- 核心模型无选择依据、验证不足或关键参数无来源；
- 候选比较尚未完成却在问题分析中写死最终模型，且后文没有真实选择证据或因此掩盖了核心模型风险；
- 数据泄漏、样本口径不清或处理与代码不一致，但尚未确认已改变结果；
- 重要公式、约束或变量域缺失；
- 论文重点公式与前文定义冲突，但尚无代码时写 `P1 + NEED_CODE_CONFIRMATION`；不得直接要求重算；
- 关键图表不可读或重要结果解释不完整。
- 正文使用手工 `（2）`/`[2]` 冒充 citation、正文与文末编号样式冲突、citation key/文末条目/PDF 跳转错配，或普通区间/集合被确认错误链接到参考文献。
- 对照原题/附件后确认：本队设定、模拟生成或数据估计的参数、相关矩阵、关系边、分布、阈值或权重，在正文中被写成“题目给出/根据题设”。
- VISUAL_ONLY 或 FULL 的最终 PDF 仍出现“待绘制/待插入/此处插入”等图表占位。

### P2 — 中优先级完整性/可读性问题

典型情形：

- 图表裸接小标题、缺少图前口径或图后量化解释；
- 动态标题被机械四段式替代；
- 参考文献格式、孤儿引用或次要编号问题；
- 缺少次要基线、参数敏感性说明或附录说明；
- 图表冗余、尺度不一致、较明显版面空白。
- 关键章节转换缺少承接关系，读者无法判断新模型、约束或验证为何出现；
- 大段模型百科替代了本题适配理由，或复杂长句/抽象名词堆叠明显遮蔽方法与结论。
- 同一技术概念、动作、模型或方案在全文反复换名且没有定义差异，影响读者追踪；
- “相关方法见文献”“具体算法参见文献”“详见文献”等展示式引用反复出现，造成模板感或使文献支持对象不清。
- 同一方案在新的统一评估集、联合情景或参数口径下重评得到不同数值，但论文未说明口径变化；

### P3 — 美观与语言优化

典型情形：

- 元话语、套话和概念链偏多；
- 个别长句、多层连接、抽象名词堆叠或局部过渡生硬，但不妨碍数学含义；
- 个别术语笔误或局部展示式引用表达，不影响引用真实性和主张定位；
- 个别页面密度、留白、图例位置或字号可优化；
- 不改变数学含义的错别字、标点和轻微格式不一致。
- `log D` 等对数变量未单独写指数反变换，但上下文尺度明确且未造成结果口径错误；
- 已有有效 `parindent`，仅混用人工缩进或局部源码写法，最终视觉正常；

### UNVERIFIED 与 N/A

- `UNVERIFIED`：当前模式内部所需材料不足或工具无法可靠确认；必须列出补充证据。属于下一模式的材料改用 `DEFERRED_TO_FULL / OUT_OF_SCOPE`。
- `N/A`：任务结构确实不适用；必须写原因，不能用来规避审查。
- 普通邮箱、参考文献 GitHub、元数据作者字段、PDF 无文本层、自定义 LaTeX 宏和字体别名默认进入 `UNVERIFIED`，不能自动升 P0/P1。
- P2/P3 可以标 `WARN`；启发式命中只有在人工确认后才可提升严重度。

## 3. 发现项写法

每个 P0/P1 使用以下字段：

```text
[P0][M10 模型—代码—结果一致性] 标题
位置：论文 7.2 / problem2.py:145 / result2.xlsx:Sheet1
证据：正文目标函数含 CVaR 项，最终代码目标仅包含期望利润。
规则：S1 模型—算法—程序—结果一致；反向证据链不得断裂。
风险：论文声称的风险方案不是代码实际求得，结果不可复现。
建议：确认最终模型；若 CVaR 为正式模型，修正代码并重跑全部 Q2 结果及图表，再复审。
自动修复：否
判断类型：DETERMINISTIC / SEMANTIC / VISUAL / HEURISTIC
阶段状态：CONFIRMED_IN_SCOPE / NEED_CODE_CONFIRMATION / RECOMPUTE_REQUIRED / …
```

P2/P3 可以更短，但仍包含位置和具体建议。避免“模型不合理”“图不好看”等无证据评论。

## 4. 固定报告模板

```markdown
# FINAL AUDIT REPORT

## 1. 总结

- Overall Status: NOT_READY_TO_SUBMIT
- Audit Mode: FULL
- Rule Baseline: 2026 S0 + 用户 C 题规范 S1
- P0: 2
- P1: 3
- P2: 6
- P3: 4
- PASS: 82
- UNVERIFIED: 5

一句话结论：当前不能交卷；先修复结果约束与模型—代码不一致，再处理摘要和图表问题。

PAPER_ONLY 时改用 `PAPER_AUDIT_*`，并明确“该状态不是可交卷结论”。

## 2. 审查范围与缺失证据

| 材料 | 状态 | 说明 |
|---|---|---|
| 原题与附件 | VERIFIED | … |
| 最终 PDF | VERIFIED | SHA/文件名/页数 |
| 最终代码 | VERIFIED | 入口… |
| 支撑材料 | UNVERIFIED | 缺少… |

## 3. Audit Coverage

PAPER_ONLY 与 FULL 均必须逐行显示核心模块；PAPER_ONLY 使用 `PASS / WARN / FAIL / UNVERIFIED`，并把 P0—P3 写在最后一列。不得省略未发现问题的模块。

| 核心模块 | 状态 | 证据/位置 | 主要问题或通过依据 | 严重度/缺证 |
|---|---|---|---|---|
| 段落与排版源码 | … | … | … | … |
| AI/模板化语言 | … | … | … | … |
| 长句与可读性 | … | … | … | … |
| 段落/小节过渡 | … | … | … | … |
| 模型百科式表达 | … | … | … | … |
| 术语一致性 | … | … | … | … |
| 问题分析与最终模型边界 | … | … | … | … |
| 模型选择证据链 | … | … | … | … |
| 跨问接口 | … | … | … | … |
| 模型输出→最终决策映射 | … | … | … | … |
| 图表正文叙事 | … | … | … | … |
| 公式与符号 | … | … | … | … |
| 引用格式 | … | … | … | … |
| 引用跳转 | … | … | … | … |
| 引用语义正确性 | … | … | … | … |
| 参考文献数量与正文对应关系 | … | … | … | … |

### Deferred to FULL / Drawing / Out of Scope

| 检查项 | 阶段状态 | 当前证据/原因 | 下一模式 |
|---|---|---|---|
| 代码执行与复现 | DEFERRED_TO_FULL | PAPER_ONLY 未提供代码不构成失败 | FULL |
| 图表占位 | DEFERRED_TO_DRAWING | … | DRAWING/FULL |

## 4. BLOCKER

- 仅在 NOT_READY_FOR_FINAL_AUDIT 时列出。

## 5. P0 — 必须修

逐项使用标准字段。

## 6. P1 — 高优先级

逐项使用标准字段。

## 7. P2 — 中优先级

按模块和位置列出。

按页面或短语统计列出。

|---|---|---|---|---|---|

## 10. 反向证据链

| 核心结论 | 表/图 | 结果文件 | 代码 | 模型/约束 | 原题证据 | 状态 |
|---|---|---|---|---|---|---|

### 题面事实与模型设定来源矩阵

| 参数/关系 | 正文声称来源 | 实际来源/证据 | 状态 |
|---|---|---|---|
| … | 题设/附件/本文设定/数据估计/模拟生成/文献标准 | 原题页码、附件字段、生成方法、估计依据或文献 | PASS/WARN/FAIL/UNVERIFIED |

## 11. 结果复现与一致性

| 检查 ID | 重算输出 | 冻结结果 | hash/结构/容差 | 正文数字 | 状态 |
|---|---|---|---|---|---|

## 12. PDF 视觉审查

- 最终 PDF 文件名、SHA-256、页数、contact sheet；逐页已检查范围；视觉问题页码。

## 13. 自动审计摘要

- 运行命令、退出状态、页数/大小、字体清单、引用与匿名扫描摘要。

## 14. 连接、可读性、术语与模型叙事

- 列出关键边界、前后段职责、承接证据、是否需要修改；汇总长句/多层连接/抽象名词候选、模型适配理由和问题分析提前定模情况。
- 给出术语一致性矩阵；展示式引用表达与其实际支持对象一并检查。
- 自动候选与人工确认分开记录；不要按句长或关键词直接判定 AI 写作。

| 技术概念 | 出现变体 | 位置 | 是否同义 | 统一名称/区分定义 | 状态 |
|---|---|---|---|---|---|

## 15. 引用完整性矩阵

| 正文位置 | 引用编号/key | 当前句子声称什么 | 主题匹配 | 原文支持 | 引用位置 | PDF 跳转 | 状态 |
|---|---|---|---|---|---|---|---|

- 覆盖全部正文引用 occurrence；联合引用可同位置合并。只有题名/主题、没有全文证据时，原文支持与整行状态均不得为 PASS。

## 16. 修复顺序

1. **第一优先：正确性与交卷安全（P0）**：漏答、硬约束、结果错误、代码—论文不一致、匿名/AI/提交违规。
2. **第二优先：学术逻辑闭环（P1）**：模型选择依据、题面事实/结构参数来源真实性、跨问接口、模型输出→决策、关键验证、引用错误与引用真实性。
3. **第三优先：阅读逻辑与人工感（P2）**：连接/过渡、AI/百科式表达、术语不一致、问题分析提前定模、图表叙事和重要内容重复。
4. **第四优先：压缩与结构优化（P2/P3）**：长句、重复总结、概念链、章节过满和图表冗余。
5. **第五优先：视觉与微格式（P3）**：缩进、空白、字号、图例位置和局部标点；若影响引用跳转、实质可读性或官方格式，按实际风险升至 P1/P2/P0。

原则：先审对不对 → 再审闭不闭环 → 再审顺不顺、像不像人写 → 再压缩 → 最后看美观。修复顺序不得按脚本发现时间或修改难易度排列。

## 17. 最终结论

明确说明是否允许交卷，以及仍需人工确认的项目。
```

## 5. 复审规则

- 先读取上一版报告，为每项标记 `FIXED / PARTIALLY_FIXED / NOT_FIXED / REGRESSION`。
- 只复核上一版问题及其直接依赖；检查本次修订在受影响文件、结果链和相邻版面中引入的回归，不重新打开无关模块。
- 任何改变代码、结果或核心公式的修订，重新执行模型—代码—结果一致性和反向证据链。
- 任何改动摘要、分页、图表或字体的修订，重新渲染最终 PDF 并逐页检查受影响页及相邻页。
- 只有在新最终版本上重新计数后才能提升 Overall Status。
